# PR #87 independent audit — successful named Provider identity (2026-11-03)

## Scope and verdict

Examined PR #87 at `06a092d4b10e992624c40237c95276dfbfc0221e`, notably Agent `generateProviderModel`, `executeModelInvocation`, external unary/SSE completion and replay boundaries, the shared-budget authority hook and existing tool-effect regressions. Found and reproduced one new **P1**, fixed without changing Kernel, Store, Tool payload or replay formats. Existing unrelated untracked local probe scripts were preserved.

## P1: a successful named Provider response can authorize Tools without a physical response ID

**Original behavior:** `executeModelInvocation` checked exact physical `ResponseID` only when the Provider returned a typed *rejection*. Successful named external Provider replies with empty or whitespace-padded `ResponseID` could still be consumed. Agent persisted a missing/normalized `ProviderResponseID`, leaving no stable identity for the same-Run duplicate-completion fence. Additionally, `generateProviderModel` silently trimmed streamed terminal `ResponseID` and did not reconcile that ID against the returned final response. A custom upstream adapter or middleware could therefore authorize a local Tool with contradictory physical identity evidence.

**RED evidence:** Added `TestNamedProviderSuccessfulToolRequiresExactPhysicalResponseIdentity` exercising actual Agent → registered Tool handler execution. On the original PR Head (before the fix), `go test ./go/agent-runtime/agent -run '^TestNamedProviderSuccessfulToolRequiresExactPhysicalResponseIdentity$' -count=1 -v` failed in 5 of 7 initial subtests: `unary_missing_id`, `unary_padded_id`, `stream_missing_id`, `stream_padded_event_id`, `stream_mismatched_event_id`. Each invalid case physically ran `effects=1`, completed the Run and consumed two LLM receipts. Both valid controls passed.

**Fix:** For named Provider bindings, reject successful/late and known rejected completions when their physical ID is absent or changed by whitespace normalization. Check once immediately after physical Provider return (before shared-budget settlement), then again after middleware and before durable ModelInvocation completion. Preserve exact SSE terminal IDs, reject conflicting repeated SSE identities and disagreement between SSE terminal evidence and the Provider's returned final response. Retain a conflict even if a faulty StreamingClient ignores the stream sink error. Never normalize an ID to invent valid authorization. Keep unnamed local Model clients' optional ID contract unchanged.

**P1 recovery bypass:** The same exact-ID fence was missing when validating durable, already `completed` or `consumed` named Provider ModelInvocations. Existing `validModelInvocationReceipt` accepted unverified old receipts on restart; a completed Tool-bearing invocation could resume without passing the live Provider guard. Added 28 persisted-state matrix cases covering both lifecycle states, successes and known rejections. Before the fix, all 20 invalid named-identity states were incorrectly accepted; 8 valid named/unnamed controls passed. The state validator now rejects missing, normalized or inconsistent physical IDs, and malformed named bindings, without changing serialized state or grandfathering unsafe Beta receipts.

**GREEN evidence:** The repaired 14-case matrix covers unary/SSE missing and padded IDs, incompatible terminal IDs, two contradictory streamed IDs (including a faulty StreamingClient that ignores callback errors), late middleware mutation of otherwise valid IDs, and valid unary, SSE-final-only and event-only completion controls. `go test -race ./go/agent-runtime/agent -run '^TestNamedProviderSuccessfulToolRequiresExactPhysicalResponseIdentity$' -count=5` passed. An older named-Provider limiter test fixture had returned an ID-less success; the fixture now returns an exact stable ID per Run and retains its original concurrency/binding tests. The persisted-state matrix passes after the recovery validator fix; targeted Race and full Agent tests are green. All Agent Runtime, Harness and Provider module tests passed with `go test ./go/agent-runtime/... ./go/agent-runtime-harness/... ./go/agent-runtime-provider/...` before the final recovery hardening, which subsequently passed its own Agent tests.

## Compatibility and residual risks

This is a pre-stable contract hard cut: *named external* Provider implementations must return a nonblank, exact original physical completion ID on **successful** responses as well as known paid rejections. An adapter that cannot provide the physical ID cannot authorize a successful tool-bearing or text-only completion under a named binding; it must fail closed, rather than synthesize an ID from local state. Existing persisted receipts are not rewritten; a legacy named-Provider receipt without exact physical identity fails state validation rather than being silently trusted on restart. No legacy fallback, compatibility bridge, migration, protocol version increment or Kernel/Store schema change is introduced. This audit uses deterministic local mock providers and tests; live upstream gateways, credentials and production network behavior were not validated here.
