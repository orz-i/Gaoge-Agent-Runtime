# Managed recovery v3: exact state machine proposal, not implemented

Scope: only the existing first-party managed Root Session crash at the second `agent.model_invocation.pending` ApplyExecution commit. Keep the crash interception and actual process exit. No callback-return fabrication, no generic middleware issuer, no shared-database assumption. This supersedes the tentative Host-first order in v1.

## Existing facts and package boundary verified
Harness is a separate Go module importing Core. Core cannot import Harness or let Harness import Core internal/featurecontrol. Kernel already has opaque proof wrappers (OwnedPhysicalAdmission/Recovery), native lease Acquire/Renew/WithExecution, and exact owned grants. Model dispatch persists DispatchAttempt before actual Generate. Existing pending intent with DispatchAttempt=0 and prior complete receipts supplies unsent evidence; it does not supply whole-stack suspension. Existing callbackscope.Operation is only process-local and Record occurs after Next returns. Existing BoundedContextAdapter owns Hydrate→Next→internal Record; Prepare owns actual artifact writes, checkpoint CAS, read-back, Bind and materialization. Existing ordinary Context constructors do not acquire bounded status automatically.

Reuse existing authorities, but add a narrowly typed suspension and handover transition. This is a new durable transition, not reuse of callback-return or no-effect flags. Core types stay Core-owned; Harness data are carried as neutral immutable identifiers. Verification of Host state is through a configured storage authority port, never arbitrary middleware assertions.

## Trust and wiring (explicit, not generic trusted callbacks)
The trusted Store is already the persistence authority in the SDK threat model. This design does NOT defend against an implementation of Store that lies about committed state. It must defend against callers supplying IDs, ordinary middleware, stale handles, and inconsistent persisted records.

Define a narrow Core `ManagedRecoveryHostStore` storage port with fixed methods: `ReadOriginalDispatch(binding)`, `ReserveManagedRecovery(binding, parkedProof)`, `ReadManagedRecovery(binding)`. The only supported implementations initially are the concrete existing Harness Memory/PG Store adapters implementing the exact transactions below. No function callback, arbitrary `Completed` flag, public receipt mint, or pluggable lifecycle issuer is accepted. Harness constructs the concrete native managed bridge with its actual Store and original validated Invocation/dispatch. The exact Core Runner is configured with that bridge; replacement at Resume is validated against stored Host authority namespace plus immutable records. Construction/wiring is trusted configuration, like supplying Kernel.Store, not authorization from user-controlled Run input.

Core owns exported opaque read/park/enable proof values with unexported fields; they are made only by Runtime methods that perform actual Kernel reads/CAS and the fixed Host storage checks. Harness cannot directly seal featurecontrol proofs. Host Store validates opaque Kernel parked proof and full immutable binding before its transaction, then independently validates its own persisted records under the Turn lock. There is no universal adapter taking an arbitrary function and certifying its return. Persistent data contain IDs and hashes, not serialized Go capabilities; a fresh process reacquires proof only by actual authoritative Store reads. Host namespace must be a persistent stable Store identity, not a database URL or caller-chosen arbitrary token. Existing supported Store metadata must be inspected during implementation; if no identity exists, add dedicated immutable recovery authority metadata, not an authentication credential.

This is an explicit additional trusted STORAGE seam. If the requirement instead forbids any new storage seam and demands Core verify a foreign Host DB without reading it through trusted storage, cross-store proof is impossible. That restriction would be a separate major tradeoff, not something a public boolean can solve.

## Durable objects and keys
All IDs are canonical deterministic encodings with domain separation, not user-supplied evidence.

K.safe: primary key (original Root grant ID, pending ModelInvocation ID, pending revision). Contains unique suspension ID; full original grant/lease/epoch; exact Run identity/revision/state hash and checkpoint; pending full request/hash/provider/catalog binding; prior receipt and budget state digest plus original persisted source; Context checkpoint/artifact source; exact bounded lifecycle version; Host namespace/Turn/Invocation/attempt/executionRef/original dispatch ID/phase/frozen source. State AVAILABLE, INVALIDATED, PARKED, ENABLED, REJECTED. Stored alongside source mutation in Kernel transaction.

K.transfer: one-to-one primary key suspension ID, recovery ID = domain hash(suspension ID + complete Host binding). Contains old grant, source revision, state, expected Host reservation ID, immutable predecessor, winning successor grant/lease/epoch only after ENABLE. No second reservation ID is created when process dies. PARKED has NO execution owner/lease capable of dispatch, and is not assigned to the process that happened to park it.

H.recovery: primary key original dispatch ID, unique recovery ID. Contains exact suspension/Kernel source binding, original Invocation/attempt and original dispatch, status RESERVED or CLOSED/REJECTED, plus eventual authoritative Kernel result. Original dispatch remains pending and its history immutable. Reservation is NOT callback completion, and cannot coexist with another recovery ID or conflicting original completion.

K successor uses a unique winning per-call claimant nonce at ENABLE; owner/lease are not shared by all recovering processes. Public deterministic recovery ID is not an execution credential.

## Whole-chain eligible safe point
Only exact native managed Root with the specific Runtime BoundedContext orchestration and no arbitrary Run/Model/Tool middleware is initially eligible. Do not include Budget/Timeline/other adapters merely because they are bounded. Registry/provider calls already returned and their full receipts are durable. No ToolDispatch, ToolWait, deferred child, dispatched pending Model, active async Next, or outstanding external callback. Context Plan/meter/storage calls have actually returned successfully; required checkpoint/artifact commits and read-back are complete. Hydration frame is parked around the synchronous native Next and has no external post-Next action, only Runtime journal bookkeeping. Static continuation program version identifies that exact tail.

Add internal scope state for this exact adapter: active synchronous frames, returned concrete operation results, pending child callbacks, and a suspension barrier. It can produce a suspension descriptor only when the current Agent driver owns the single continuation and all non-Next callbacks have returned. A generic success/error or context hash is insufficient. No asynchronously outstanding branch or retained middleware context gets eligibility.

Descriptor commit is in the SAME existing ApplyExecution transaction as `agent.model_invocation.pending`, not after its return. Runtime adds a private narrowly typed source/target proof to that mutation. Store validates exact old revision/lease/grant and new pending intent, all relevant state and source. This preserves os.Exit after the current event commit. Prior receipts and checkpoint hashes alone cannot activate this operation without the internal concrete lifecycle proof.

After the commit, original execution may proceed. Its first subsequent mutation (including model claim) atomically invalidates AVAILABLE before any new physical or Host callback. No potentially effectful preparation/discovery callback may run between the safe point and that invalidation. The exact pending-request path must move/retain the invalidation before such callbacks; dispatch CAS alone is too late if discovery runs earlier. If any unjournaled callback remains in that interval, this path is ineligible rather than assuming it pure. Old-owner writes check the original lease and AVAILABLE/PARKED state in the SAME Kernel lock/transaction.

## Transactions and transitions
### T0: normal intent commit
Kernel lock/transaction: validate native owner and original owned grant, source revision and lifecycle proof; write pending intent plus AVAILABLE descriptor atomically. No Host write. Original owner may continue only through ordinary lease-fenced mutation that invalidates the descriptor before external work. Crash at existing test hook leaves AVAILABLE.

### T1: PARK, Kernel FIRST
Recovery first performs read-only Session/frozen Invocation/Host dispatch authorization checks. Then Kernel transaction locks Run/grant/safe/transfer using one consistent order. Check exact source unchanged; AVAILABLE; prior receipt completeness; pending DispatchAttempt=0; no unsafe active effects; actual Store clock says old lease expired. Check exact old lease owner/ID/epoch and unchanged expiry against current record. If still live or renewed, reject with execution conflict and perform NO Kernel or Host mutation. No Host reservation has been written yet, so liveowner rejection leaves FULL Host unchanged.

If checks pass, change AVAILABLE→PARKED and create unique transfer. Set an explicit recovery fence on original grant/lease authority; do not claim callback complete or delete old grant. Epoch can remain numerically old until ENABLE, but all Acquire/Renew/Apply/ApplyExecution/ApplyControl and physical admission paths must reject that parked old authority. No executor owns PARKED. This is authority revocation at a proven unsent/quiescent cut, not assignment of a live execution lease to a recovery coordinator.

Old-owner renew vs PARK is serialized in the same Kernel transaction: renewal first makes it live and PARK rejects with no Host writes; PARK first revokes old authority and renewal fails. Old-owner model claim vs PARK similarly has one winner: claim first invalidates AVAILABLE, so PARK fails; PARK first prevents claim/any send. A clock read before the transaction is never authority.

### T2: reserve exact Host recovery
Obtain opaque PARKED proof by Runtime read of exact K.transfer/source. Host transaction takes original Turn lock and locks original Invocation/dispatch/recovery records. Validate Session actor/thread/frozen original source, same Invocation attempt/ref, original dispatch phase and physical run, no conflicting completion or cancellation/retry authority, and exact bound namespace. If valid, create H.recovery RESERVED using fixed recovery ID; identical replay returns same row. Keep original dispatch pending, now associated with this reservation. This blocks other dispatch/cancel/retry exactly as the original pending dispatch did. No caller can invent another successor by presenting the public recovery ID.

If cancellation/terminal/identity conflict won before reservation, do not reserve. Return a typed deterministic rejection. Kernel may mark PARKED→REJECTED only with verified terminal/conflict Host state from the fixed storage port and appropriate source checks; it never restores old execution authority or sends anything. Cancellation/cleanup must then use its own existing authority. This branch needs a dedicated no-dispatch assertion, not a false successful recovery. A transient Host error leaves PARKED recoverable.

### T3: ENABLE, Host ACK before dispatch
Runtime fixed bridge reads RESERVED H.recovery and original immutable Host binding through configured Store. Host RESERVED is durable and NON-REVOCABLE until Kernel proves successor terminal/quiescent/rejected: cancellation/retry cannot remove or replace it concurrently. Thus reading it before the Kernel transaction has no TOCTOU authorization gap. A generic mutable status read would be unsafe.

Kernel transaction verifies PARKED transfer, same suspension/source, and the opaque Host-read proof tied to Runtime's configured authority. CAS PARKED→ENABLED, bump native epoch once, allocate unique winner's native lease and successor owned grant, and persist exact handover lineage. Old grant is marked suspended/transferred, not callback-returned. The successor uses existing frozen pending request and valid receipt state. Only this transaction opens dispatch permission. Before it, every model/tool/Host effect boundary is blocked by PARKED. Two callers: only one CAS gets the new owner/lease; loser receives conflict, never the winner's raw execution authority. Exact ACK-loss retry is limited to the same per-call claimant nonce and bound lease; a new process cannot adopt an active lease merely by knowing recovery ID.

No further Host ACK is needed: T2 is already the durable ACK. Host association stays RESERVED while successor executes. This removes v1's unsafe Kernel-enabled-before-Host-ack window.

### T4: actual result and closure
New owner resumes original intent without re-Prepare, transcript or prior Tool replay. Any required read-only Context hydration is owned by the bounded adapter and checked against persisted source. New actual callback returns/settles under existing Root protocol. Host records actual successor result and closes original dispatch as transferred plus successor completed, not original callback returned. Recovery history remains explicit and source-bound. These Host writes use original Turn lock and deterministic completion identities; ACK loss is resolved by exact reads.

## Crash recovery permissions at every boundary
- Before T0: existing rules, no new recovery authority.
- T0 committed/ACK lost or old process exited: fresh authorized Session may attempt T1; live lease still refuses without any Host mutation.
- T1 committed/ACK lost: read same PARKED transfer. Any correctly authorized Session coordinator may finish T2/T3; it cannot execute or change source while PARKED. No coordinator lease is required because no coordinator owns effects.
- T2 committed/ACK lost: read same RESERVED row and same transfer; no new election/reservation. Finish T3.
- T3 committed/ACK lost in SAME live caller: exact nonce+lease read returns own result. Other caller rejects until owner lease expires.
- New process dies after T3 before any mutation/effect: source still identical and activation has a persisted pre-effect continuation certificate. After lease expiry, atomically park the same recovery record again with activation-generation CAS, then re-enable one new owner. Reuse H.recovery; do not create a second original reservation. Each real successor ownership epoch increments normally; the no-extra-crash original test remains old epoch+1.
- Dies after first mutation: AVAILABLE source has been consumed. Recovery requires a newly recorded eligible safe point from the SAME concrete mechanism; absence or unknown dispatched effect stays Unknown. Never recycle the old certificate.
- T4 Kernel complete/Host ACK missing: read exact actual Root completion and transfer lineage; repair original Host closure only, no physical Resume.

## Supported Store semantics and schema impact
Identical state machine in Memory lock, native SQLite write transaction and PG row transactions. Kernel and Host may be different databases or different supported Store kinds. No transaction spans them; safety comes from Kernel-first fence plus non-revocable Host reservation plus Kernel-enable CAS. Liveness assumes eventual availability of both Stores and correct authorized recovery calls; permanent Store loss cannot be transparently repaired.

Add dedicated persisted safe/transfer state and Host recovery reservation schema/version and typed Store methods. Same field checks, key uniqueness and idempotency across Store implementations. Existing owned grants/lease checks gain PARKED gating. Existing read-only receipt recovery cannot open the new gate. No legacy-row backfill of suspension proof. Records lacking new capability remain Unknown. Ordinary constructors keep opaque behavior; explicit existing bounded adapter is required for this positive path. No real-data migration authorized here.

## Closed choices and approval boundary
Selected design is Kernel-first PARK → durable non-revocable Host RESERVE → Kernel ENABLE. It handles liveowner full-Host-no-mutation, renew competition, separate Stores, Host ACK before any send, and one durable original reservation across crashes. It does not claim current APIs implement these transitions.

Necessary new trust is a narrow configured STORAGE authority bridge, not a middleware issuer. If that is disallowed, no safe cross-store recovery can be implemented with current APIs: Core cannot infer foreign Host admission from its own DB, and Host cannot certify interrupted arbitrary callback completion. The remaining decision is approval of this explicit protocol/capability extension and its compatibility boundary, not an unresolved algorithm choice. Restoring automatic recovery for arbitrary opaque middleware would require a different major promise and is excluded.

Implementation review must verify the claimed callback-free interval after intent commit and before invalidation, all parked authority entrypoints, exact schema keys, and the narrow bridge's Store registration/identity. Failure to establish any of those rejects the implementation; it must not be patched with callback-return=true, generic trust, or relaxed tests.

## Acceptance set
Keep original true process test and all existing result/source/receipt/context assertions. Add deterministic renew-vs-PARK, old claim-vs-PARK, two recovery claimants, every transaction ACK-loss and process exit boundary, mixed Host/Kernel backends, repeated same reservation, ordinary/unknown/changed-source negatives, failed Host reservation no-send, parked public Apply/Control/Acquire/Renew rejection, and T4 repair without replay. No tests or repository changes performed for this draft.

# V3 normative corrections: three closed details
The following overrides the corresponding v2 wording; other transitions remain unchanged.

## 1. Stable authorities, initial association, and opaque proof inputs
Each supported Kernel Store and Host Store adds a dedicated singleton authority metadata record: key `managed-recovery-authority/v1`, fields protocolVersion=1, random 256-bit namespace, generation=1. The namespace is generated by the concrete Store at initialization and inserted-if-absent under its schema/initialization transaction; losers read the existing value. It is not a user option, URL-derived ID, secret, or middleware input. Memory generates once per Store instance, and retains it only for that actual instance. SQLite persists it in its database; PG persists it in its isolated schema. Opening another connection or restarting reads the exact same metadata. Metadata insertion does not backfill any recovery proof into existing Runs. Do not create/rotate it lazily during a rejected live-owner recovery call.

A consistent exclusive restore of the original Host+Kernel pair preserves their namespace and generation. An independent clone intended to execute concurrently is a new authority pair: initialize new namespaces and prohibit adoption of copied in-flight safe points. A mismatched/partial restore cannot recover those points. A copied database cannot be distinguished locally from the original if both are operated simultaneously with identical metadata; preventing concurrent activation of an exact backup is an operational exclusive-restore requirement, not a cryptographic guarantee of this protocol. No automatic namespace rotation to make old evidence pass. Changing this exclusive-restore assumption would require an external fencing service and is outside this finite recovery guarantee.

Original association is created during the REAL native Harness dispatch path, after beginPhysicalInvocationDispatch has committed its actual original Item and before invoking the exact Agent. The concrete bridge reads the saved Item, Invocation and Turn under authoritative Host storage checks and compares the full existing frozen identity/attempt/phase/resultRunID. It obtains the actual Host namespace and the actual configured Kernel namespace. It supplies only a private bound-call context to the exact native invocation. Core verifies that context belongs to the configured bridge and current actual invocation; arbitrary context strings/StartRequest fields cannot supply it. At Root owned admission, Core adds the actual grant and lease/epoch. T0 writes the entire association alongside the safe point. Resume does not reconstruct association from current caller preferences.

Opaque values are specific Core public types with unexported payloads and internal constructor paths:
- OriginalBinding: protocol version, Kernel namespace/generation, Host namespace/generation, Run identity and source revision/hash, actual Host Turn/Invocation/attempt/original dispatch ID+phase, actual native call nonce, Root grant full admission binding, lease ID/owner/epoch. Constructed by the actual native bridge/Root entry sequence, not a general exported Seal.
- ParkedProof: all OriginalBinding fields, suspension ID, deterministic recovery ID, expected Host reservation ID, exact safe source revision/hash, PARKED state, transfer generation and Kernel record revision. Constructed only by Runtime after Store PARK commit or exact read-back; method verifies against the target Host persisted binding and expected configured Kernel authority.
- HostReservationReadProof: both namespaces/generations, suspension/recovery/dispatch IDs, original phase, full frozen source, Host reservation status and record revision, transfer generation. Constructed by Core only after its configured concrete bridge performs the fixed authoritative Host lookup. A caller cannot construct it from JSON or a boolean. An arbitrary custom Store is not promoted by implementing an interface: this mode is explicitly wired to supported concrete adapters, under the same trusted-Store threat model as existing execution.
- EnableResult: previous fields plus new grant, winning claimant nonce, native lease/epoch and activation generation, Kernel transaction revision. Returned only to the winning actual call; a different caller may read lineage, not acquire the winner's lease by reading recovery ID.
All verifiers compare protocol, both authority identities/generations, exact source and phase, and matching transfer generation; object pointer identity alone is insufficient across processes. Persistent proof is the actual Store record; opaque objects are ephemeral checked handles to it, not serialized bearer tokens. Core owns the neutral types and implementation; Harness depends on Core, so no import cycle or access to Core internal packages is required. Concrete adapter registration is narrow private first-party wiring, not a public generic proof factory.

## 2. Exact pre-callback invalidation and bounded frame completion
Actual source sequence is ensureModelInvocation pending Apply at model_invocation.go407–416 → agent.go1082 claim → configurable clock at claim line957 → claim Apply line973 → execute: clock, provider binding, catalog validation, telemetry/publish → eventual dispatch CAS. Therefore neither claimed mutation nor provider dispatch CAS is early enough by itself.

Add one explicit internal `LeaveManagedSafePoint` transaction immediately after successful ensureModelInvocation and BEFORE invoking claimModelInvocationExecution, and at the equivalent fresh-owner continuation jump BEFORE any clock/catalog/provider-binding/observer/telemetry callback. It accepts the exact source safe/transfer generation and native authority. It atomically changes AVAILABLE (normal original owner) or ENABLED-pre-effect (new owner) to INVALIDATED/EXECUTING and returns the current snapshot and an ephemeral continuation token for that exact call. It uses Store authoritative clock and internal fixed serialization only; no configured Clock, IDGenerator, Observer, Publish, Catalog, provider method or Host port is invoked first. Bound primitive monotonic/time reads inside Store implementations are allowed, not custom SDK clocks. Every actual callback listed above runs only after this successful transaction ACK.

Lost invalidation ACK: caller stops before all callbacks. It does not infer permission from seeing INVALIDATED or execute with a zero result. Read-only reconciliation may report the original transaction result, but a later process cannot prove whether the original caller received ACK and began arbitrary callback work. This state remains Unknown unless a later independently valid safe point/real completion exists. This is intentionally not automatic recovery for a different crash cutpoint; it preserves the original tested crash, which happens at pending-intent commit before LeaveManagedSafePoint. Parent must not claim that every pre-provider interruption is recoverable.

For the T0 proof, internal instrumentation must track concrete bounded frame phases, not just type assertions: HydrationSucceeded with actual source; NativeNextActive as the sole synchronous continuation; PrepareNotEntered or PrepareReturned with exact incoming/output request and source; all actual suboperations returned; no outstanding callback ticket. BoundedContext Prepare MUST record completion on EVERY successful early return (nil checkpoint; within soft budget; within hard budget without owner/reader; no suitable compaction) as well as successful compaction. Early paths record their actual read/assessment result and source, without inventing a checkpoint write. Compaction requires acknowledged artifacts+CAS+readback+Bind before PrepareReturned. Any error, panic, async overlap or incomplete port call makes T0 ineligible. Previous model/tool callback tickets must be returned and have complete durable receipt source. Custom preparation outside this concrete adapter is ineligible. Configured clock/observer work which completed before T0 need not be replayed; future calls occur only after invalidation. Hydration's unreturned outer frame is suspendable only because its remaining tail is the audited internal journal action, with no Host callback after Next. No claim of original whole callback completion is made.

The continuation after T3 loads only the sealed pending request and persisted Context facts using the bound first-party read path. If rehydration itself invokes any configurable callback or additional Host operation, LeaveManagedSafePoint must precede it too; a crash there then has Unknown semantics. It cannot call ordinary Resume and let unrelated prelude callbacks run before the gate. The dedicated jump point remains inside the native Agent continuation, not a user-provided function.

## 3. Permanent Host conflict and cancellation cleanup
Actual PG source disproves a blanket assertion that pending dispatch forbids cancellation intent: store.go1413 calls checkCancellationFenceTx when appending hcancel; that checks existing cancellation fences, not pending dispatch. Harness cancellation_fence.go138 performs its own pending-dispatch checks and native exceptions, but a cancellation intent may already exist or win in a legal race. Thus T2 must handle a genuine cancellation conflict; saying 'use normal Control while PARKED' is wrong.

Replace v2 generic REJECTED cleanup with these exact branches:
A. transient I/O: keep PARKED; no mutation beyond same reservation retries.
B. malformed/mismatched source, unsupported authority generation, contradictory history: remain fenced/quarantined, no generic terminalization. Such corruption cannot grant cancellation rights.
C. valid original pending hcancel targeting this exact root: Host transaction under original Turn lock creates ONE cancellation-resolution reservation bound to the SAME recovery ID, full original hcancel ID/Seq/payload and original dispatch/Invocation/source. It races with normal recovery reservation under the same unique original-dispatch key: exactly one mode wins, mode immutable. This reservation is a cancellation selection, NOT a receipt saying cancellation succeeded. Existing cancellation budget state remains governed by original CancelRun and its original intent; no new budget charging/refund or replacement election.

For C, a new narrow Kernel operation `CancelParkedManagedContinuation` consumes only this exact PARKED safe source and opaque Host cancellation-selection read proof. In ONE Kernel transaction: check namespaces/generations/source/transfer generation; original unsent intent and complete prior receipts; no Tool/deferred/unknown work; old authority fenced; no ENABLED owner; and exact original cancellation target. Then perform only the existing native root cancellation state transformation with original cancellation reason/source, preserve receipt and budget evidence and record a dedicated cancellation-transition result. It does not expose general ApplyControl, arbitrary mutation, child cleanup, or restore old owner. Run revision/epoch changes follow the native cancellation transformation, with old grant explicitly cancelled/transferred and never marked callback-returned. Exact retry returns its existing result; conflicting cancellation/source rejects. This is additional constrained recovery authority, not pretending existing Control already accepts PARKED.

Host then uses the actual Kernel terminal result, original cancellation election and exact original dispatch lineage to write its cancellation completion and suspended-dispatch resolution under normal Turn locking and deterministic identities. If ACK is lost or process exits, fresh authorized recovery reads the same cancellation mode and Kernel result, repairs the SAME receipt only, never calls Model/Tool. It must not append 'physical_dispatch_returned' for the interrupted old callback; a distinct original-dispatch-cancelled-before-next-effect settlement is required and verified against that exact Kernel transition. Ordinary unknown callbacks cannot use it because they have no valid safe descriptor.

If Host has become terminal WITHOUT a matching valid cancellation election/authoritative Kernel terminal result, do not use Turn.status as cancellation permission: reject/quarantine. Legitimate completed/failed terminal proof, if it exists, is reconciled read-only against the exact original source; it cannot coexist with an unchanged PARKED Running source under compliant Store fencing. Such a contradiction is not the normal managed recovery path and must stay fail-closed.

This closes the legal cancellation race without opening generic Control or dropping an intent. It adds one exact source-bound terminal transition to the same protocol. If authorization disallows that extra narrow transition, preserving cancellation that wins between T1 and T2 is impossible with PARKED's mandatory Control fence; the explicit alternative would be freezing cancellation indefinitely or excluding the race, both unacceptable silent capability reductions. This draft selects the narrow transition, subject to parent implementation approval, not those reductions.

No repository modifications, tests, commits, or database actions in v3 drafting. Existing real crash point and complete positive result assertions remain mandatory.


## Final normative mode binding (overrides every generic RESERVED predicate above)
Every H.recovery durable record, HostReservationReadProof, cancellation-selection proof, Kernel transfer selection, and exact read-back/CAS includes immutable Mode with exactly RESUME or CANCEL. CANCEL additionally includes the original cancellation intent ID, Seq and canonical full payload digest, alongside its complete existing target/source/namespace/phase/generation bindings. RESUME requires those cancellation fields absent. A RESERVED state without a mode is invalid and cannot authorize any transition.

ReserveManagedRecovery creates the unique original-dispatch/recovery-ID row with its mode once under the Turn lock. Identical retries require full equality of mode and all cancellation/source fields. Another mode, intent ID, Seq or digest conflicts with zero mutation. Subsequent activation generations, new process ownership, ACK reconciliation, terminal settlement and original-dispatch closure retain the original mode and cancellation binding. No retry, successor epoch or generation may reinterpret the same recovery ID.

Kernel ENABLE checks Mode==RESUME in its opaque proof AND bound transfer CAS; it rejects CANCEL even when its Host row is RESERVED. CancelParkedManagedContinuation checks Mode==CANCEL and exact intent ID/Seq/full payload digest in proof, stored transfer selection and source-bound terminal mutation; it rejects RESUME. The first mode selection written into Kernel transfer must agree with the uniquely committed Host row and is immutable. All fresh proof reconstruction validates this exact tuple, not merely row existence/status or recovery ID. Host terminal receipts are checked against the same mode, so cancellation selection can never be consumed as physical dispatch permission.

## Independent design verdict and implementation hold
Independent reviewer review_host_canonical_adoption read v2 and v3 without running tests or editing code. Kernel-first ordering closes the live-owner/renew and ACK-before-send problems. V3 namespace, exclusive restore, original association, pre-configurable-clock invalidation and early-return frame details close the remaining bounded design items. Reviewer identified the final mode cross-authorization ambiguity; the immediately preceding normative section seals that exact issue. With this mode binding the design may enter a separately parent-authorized limited implementation, NOT functional acceptance. CancelParkedManagedContinuation is a new narrow persistent authority transition, not a fixture or reuse of ordinary Control. Implementation remains on hold pending explicit parent authorization of that addition. No new protocol source code has been written.
