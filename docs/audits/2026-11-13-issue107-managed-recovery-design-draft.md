# Managed session crash recovery: limited design draft, not implementation approval

## Scope and observed failure
Only TestRealPostgresManagedAgentSessionRecoveryAcrossProcessCrash, at its existing second `agent.model_invocation.pending` commit followed by os.Exit(77). Keep that exact event/commit cutpoint and the real new process. First Model and subtotal Tool have durable receipts; next Model has not reached Generate. Preserve original Run/Invocation/attempt, frozen request, archived Context, nil TranscriptSource recovery, and one append-only external Tool ledger entry. No change to unknown-provider, arbitrary middleware, delegated child, cancellation, or other recovery protocols.

Current blocker is two-level: original Harness Start dispatch has no completion, so PG rejects the new Resume dispatch before Agent lease admission. Independently, Root owned grant has no callback-return/settled mark; clean prior receipts do not retire it. Current assertion expects native lease conflict and later takeover, but neither is reached. This is an existing recovery guarantee to preserve, not an assertion to weaken.

## Existing authority to reuse first
- ModelInvocation frozen ID/request/hash/provider binding plus DispatchAttempt=0 is existing evidence that this particular Model has not crossed the SDK dispatch CAS. Existing claim/release logic refuses nonzero DispatchAttempt. Reuse it; do not invent a provider no-send declaration.
- Exact native ExecutionLease owner/lease/epoch, Store authoritative expiry, Run revision and OwnedPhysical grant already fence writes. Reuse their lock ordering and validation.
- knownRootPhysicalSettlement checks prior Model receipts and excludes outstanding ToolDispatch/ToolWait/deferred children. Reuse this predicate, strengthened with the precise pending intent and source comparison; it alone proves no whole-Host completion.
- RecordOwnedPhysicalCallbackReturn / ReconcileRootPhysicalExecution require actual returned callback or existing mark. They cannot be used here: os.Exit interrupts Next. Do not set HostCompleted=true or mint a return receipt.
- ReconcileModelOutcome handles dispatched invocations with authoritative response and a callback-return record. This intent is unsent and no return exists, so this is not its domain.
- Native start/control no-effect evidence only describes those actual preflight paths. This Start already ran Model/Tool and Context operations. Cannot reuse no-effect markers.
- Existing Harness original dispatch admission/completion and PG per-Turn serialization bind Host owner and arbitrate cancellation. Reuse that infrastructure, but current completion vocabulary means returned/rejected, not suspended/transferred.

Conclusion: existing unsent state and fences are necessary but insufficient. The missing fact is **Runtime-owned continuation suspension at this source point**, and its linkage to the still-open Host dispatch. This is a narrowly new state transition on existing authorities, not a new general recovery framework.

## Lifecycle owner and eligibility
Explicitly migrate this managed fixture to the existing concrete Runtime BoundedContextAdapter for Run hydration and Prepare. Ordinary NewContextRunMiddleware / arbitrary PrepareModelRequest remain opaque and cannot opt in by name/boolean/error. Constructor migration alone is insufficient: its current Record occurs after Next returns, and its operation journal is process-local.

Eligible path for this draft is exact first-party managed Root Agent + concrete bounded Context orchestration only. No arbitrary Run/Model/Tool middleware or additional effectful callback may be active. Prior Model/Tool calls must have returned with verified durable receipts, all entered bounded Context ports must have returned successfully, no dispatch is in flight, and the only remaining Context Run tail is the audited internal recording operation (no external post-Next work). Do not silently include Budget or Timeline or other adapters. Plan/Assess or host callbacks that are not covered by this bounded path make the point ineligible.

At this point the Runtime owns continuation after the pending-intent commit. It may persist a **suspendable continuation descriptor**, not a statement that the whole callback completed. Include the exact adapter protocol version and Context checkpoint/artifact identities and acknowledged operation results. Persist actual state or immutable verifiable references, not just an unauthenticated hash supplied by a caller. No public Mint/Completed/TrustedIssuer API. Ordinary caller-set request fields cannot activate eligibility. Runtime internal instrumentation observes the concrete operations and assembles the descriptor.

## Durable source and Host binding
Descriptor must bind: original Root grant ID and full immutable admission source; native owner/lease/epoch; Run ID/revision/Actor/thread/request ID; original Host Turn and Invocation IDs, execution class/ref/attempt/frozen identity; original Host dispatch ID/phase; pending ModelInvocation ID/full request hash/catalog and provider binding; exact prior receipt set and budget state; Context checkpoint generation/source/artifact identities; descriptor protocol version and a unique immutable suspension ID.

Host dispatch identifiers are not authority alone. The native Harness path must associate the actual already-admitted dispatch with this exact observed Agent call; recovery independently validates the original persisted Host records, not context strings. A new opaque association seam, if needed, must be specific to this concrete first-party call and Store-backed original dispatch validation. Do not expose a generic callback receipt issuer. Exact API and package boundary need review: core cannot import Harness. A narrow data binding plus a concrete Host verifier/transaction adapter can carry it, with Kernel/Host validations independent and neither accepting ID existence as proof.

## Atomic safe-point commit (preserve existing crash cutpoint)
Safe-point descriptor must be persisted in the SAME Kernel transaction as the existing second `agent.model_invocation.pending` state/event commit. A write after ApplyExecution returns is too late: the test exits immediately after commit. Add narrowly typed metadata/operation support to the existing mutation/OwnedPhysical Store seam, with a private Runtime-generated proof; Store verifies old revision, exact current native lease and grant, before/after state, pending DispatchAttempt=0 and all receipt/source invariants. Memory uses its lock; SQLite/PG use the current transaction and lock order. Never infer eligibility from event text alone.

The descriptor initially says AVAILABLE at source revision, not callback returned. On ordinary uninterrupted execution, the next claim/dispatch mutation invalidates or consumes it atomically. Any subsequent Run mutation or lease/grant transition that changes its source must make it unusable; recovery must compare full source revision/state even if a stored AVAILABLE flag remains. A live original owner can continue normally. This prevents a later crash after Generate from reusing an earlier unsent point.

## Recovery arbitration and Host/Kernel transaction boundary
Session identity and frozen Root ownership checks remain first. Recovery examines the outstanding ORIGINAL dispatch rather than minting a new competing Resume grant. Do not bypass pendingExecutionDispatchTx generally.

Preferred minimum is a resumable two-phase protocol on existing stores, not assume Host and Kernel share one SQL transaction simply because this fixture uses one DB:
1. Host under existing Turn lock validates original pending dispatch/Invocation/attempt/identity and no conflicting cancellation/retry/receipt; records one exact recovery reservation tied to suspension ID and expected Kernel source. It still grants no physical execution. Repeated same request reuses its identity; another claimant is rejected. Host reservation must fence cancellation/retry as original dispatch did.
2. Kernel atomically verifies suspension AVAILABLE, unchanged source and receipts, pending dispatch=0, exact old grant/native lease, authoritative clock says old lease expired, and validated recovery binding. It consumes suspension, fences old epoch and replaces/transfers owned physical authority to one new owner/epoch with a durable handover receipt. This is not callback completion and must not silently retire original history. Live old owner is rejected without partial mutation. Concurrent old dispatch CAS vs handover: only one wins under same Kernel lock; after transfer old lease cannot send. New owner must not send until step 3.
3. Host under Turn lock checks the exact opaque Kernel handover result against original reservation/source and records original dispatch transferred/suspended plus replacement continuation dispatch atomically (or changes the reservation into that exact successor). Only after this Host acknowledgement may Runtime drive the existing frozen intent. If Host ACK is lost, read original exact durable records; do not create another dispatch. If step 3 fails, new owner remains non-dispatching; retries only complete this same handover. Do not rollback epoch or allow original owner back.
4. Resume consumes the original frozen request, not Prepare/transcript again. Existing completed Tool remains consumed. Rehydrate read-only Context from verified persisted checkpoint only as required; no replay of old compaction or external Tool. Success records actual new callback completion normally, while original suspended history remains explicit.

This needs review before code: specifically how the new owner's `may dispatch` bit is enforced in Kernel, not merely by Harness convention; how Kernel validates Host reservation without accepting a fabricated caller boolean; and how a lost process between steps 2/3 can complete the same handover without a generic foreign-owner adoption loophole. An alternative co-located PG transaction adapter could make steps 1–3 atomic for this test, but would introduce a backend-specific guarantee and is NOT assumed acceptable or proposed as a silent replacement for current supported storage combinations.

## Safety and failure matrix
- Live lease: typed conflict, no Run/epoch/Host receipt/model/tool/budget mutation. A reservation-only write would violate that exact test invariant; therefore perform read-only liveness precheck before step 1, AND atomic Kernel expiry recheck in step 2. Race or renewal after precheck requires an explicitly recoverable non-dispatch Host reservation, and tests must distinguish that from execution mutation. Prefer a transaction design that avoids even this reservation on live-owner rejection if exact full-Host no-mutation is required.
- No descriptor/old version/ordinary middleware/pending dispatched Model/unknown Tool/post-Next effect: retain original grants and Unknown; never TTL takeover.
- Changed Actor/thread/Invocation/route/attempt/request hash/Context source: reject before transfer; no re-preparation.
- Second claimant or revived old process: one epoch owner, original source-bound successor, no duplicate Generate.
- ACK loss at intent+descriptor, Kernel handover, Host transition: exact identity replay/read reconciliation; never duplicate authority.
- Legitimate prior Tool receipt is preserved in full; pending unsent Model is not manufactured as Completed. Actual provider next request matches frozen request exactly.

## Migration and impact
Additive persisted suspension/handover data and narrowly typed Store operations require implementation in every supported primary Store if exposed generally. Legacy records without a descriptor remain fail-closed; do not backfill proof from state. Existing ordinary constructors retain opaque behavior. Existing callback-return records and HostCompleted semantics stay unchanged. No production data migration or deletion is authorized.

This restores a lost existing first-party process-recovery guarantee, but changes durable protocol, Store capability surface, and explicitly migrates this first-party configuration. It is not merely a fixture normalization. Parent/independent review must approve the exact transaction/API design and supported storage boundary before implementation. If restoring arbitrary legacy middleware crash recovery is required, this narrow design cannot prove it and must not claim compatibility.

## Blocking design questions for review (do not promise resolved)
1. Exact cross-module opaque Host reservation verification and Kernel dispatch gate, without a generic trusted issuer.
2. Atomicity/recoverability of Host+Kernel handover across separately supported stores; whether a narrowly co-located PG implementation is acceptable or insufficient compatibility.
3. Full pre-intent bounded callback journal: prove all entered adapters and Context ports are quiescent, including custom manager/meter ports, without treating arbitrary successful return as unlimited no-effect authority.
4. Exact same-transaction hook preserving existing ApplyExecution crash interception and event semantics.
