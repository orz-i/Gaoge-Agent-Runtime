## Trust boundaries and invariants

1. **Corpus versus measurement-profile identity:** The pilot uses the same `evidence-40-v1` source fixtures, Oracle and task version as the full quality suite. Context-budget policy is included in the dataset hash, and therefore a quality-only Host cap adjustment necessarily creates a **new, non-comparable dataset hash**. Archived source bytes, the fixed 40-case order and the historical two-case baseline hash remain unchanged.
2. **Physical execution cap:** The Host-only Go command `-mode=baseline-pilot-stdin` admits only the exact quality suite with `repetitions=1`. After the existing mandatory Provider preflight it can execute exactly one fixed `code-01` sample. All remaining 39 cases are structurally unreachable regardless of whether the pilot succeeds, fails or is interrupted. CLI flags cannot substitute another Provider or promote execution mode.
3. **Real effects, not simulation:** The selected case goes through `runTask`, the normal Provider adapter, actual Agent/Tool/Context/Oracle and same-Run recovery path. It is bound by the pre-existing 5-minute task budget, 12-Model-call/10-Tool-call ceilings, single-attempt model policy and strict Provider replay/invocation fences. No timeout or failure allows a second case to start.
4. **No invented full-score success:** A successful pilot is `pilot_sample_passed`, a failed attempted pilot is `pilot_sample_failed`, while a failed preflight is `failed`. Reports always carry `pilotOnly=true`, `pilotCaseID=code-01`, requested=40, attempted<=1, skipped>=39 and `complete=false`. A one-sample success rate is descriptive evidence only, not the 40-case benchmark score. Preflight usage remains separate from task usage.
5. **Fail-closed report provenance:** The Python parent refuses a child whose start event does not match the requested pilot mode. The report parser accepts exactly one `code-01-01` task sample, forbids other case IDs, repetitions, extra samples and complete/fabricated summaries, and rejects a `retry` of a pilot report that would otherwise spawn all 40 tasks.
6. **No implicit escalation or secret leakage:** `make agent-quality-pilot` and `pilot [report.json]` are explicit; reports reused by the CLI contain only the original public configuration, never credentials. API keys enter exclusively through the existing hidden input and child stdin; report files are written with private permissions, and raw opaque ProviderReplay data is never serialized.
7. **Comparison discipline:** Numerical comparisons with any pilot report are blocked, even against another pilot on an identical model, because 1/40 is not a completed dataset. Extension to other task families must use separate genuine Oracles rather than duplicating this one evidence workflow.

## Test matrix and limits

- **Success path:** Offline fake OpenAI Provider verifies exactly one unary Schema probe, two SSE Tool/replay probes and four model invocations across **one** full Agent/Tool/Context/recovery task; no second task or draft is started.
- **Model/Oracle failure:** The same selected task fails without launching any of the other 39 cases; result remains a measured failure, not a synthetic pass.
- **Untrusted inputs:** Legacy suite, wrong suite, repetitions>1 and conflicting Go CLI flags fail before Provider dispatch. Python rejects missing/false/aliased pilot mode, changed case/sample identity, second sample, forged complete summary, invalid task/usage counters, altered exit/status, and accidental pilot-to-full retry.
- **Historical compatibility:** The default 2-case dataset identity remains unchanged. The quality suite's new Host budget produces a different profile and dataset hash while preserving its fixture corpus and task version. Existing `quality`, `probe`, historical reports and conservative comparison rules continue to work; different quality hashes cannot be compared as equivalent.
- **Operational limitations (before live sampling):** The trial's results were initially unknown; the subsequent two real pilots are separately recorded below. A Provider-only preflight is not itself a task-quality observation. A passing single case is not statistical evidence about the entire suite or external effects.

## First live pilot: Host context-budget denial after two tool steps

The operator ran `pilot` with the saved public configuration from the successful preflight report, official `https://api.openai.com/v1/responses`, model `gpt-5.6-terra`, `contextTokens=1050000`, `maxOutputTokens=4096`, `reasoningEffort=medium`, and one fixed `code-01` task. Local report: `artifacts/agent-baselines/20261107T063432Z-9245d2f6.json` (ignored/private, never committed). The report passed offline validation with `status=pilot_sample_failed`, preflight `passed`, one attempted/failed task and **39 skipped**. The task physically dispatched 2 Model calls, both HTTP 200; `lookup_release` and `read_context_artifact` executed once each, but **`save_draft` never ran**. Provider usage was fully reported for the accepted Model calls: 965 input tokens, 102 output tokens (25 reasoning tokens). At the next local Context prepare boundary the task failed `context_budget_exceeded`, stage `evidence`. The last captured HTTP 200 response was an **earlier accepted Tool response**, not evidence of a Provider-side 4xx/5xx rejection.

**Causal diagnosis:** The benchmark Host had independently imposed `ContextPolicy.MaxInputTokens=8192`, even for a model with a much larger certified context window. The Context manager has no exact provider-specific pre-dispatch TokenCounter here and correctly applies a conservative serialized-byte hard upper bound including provider-owned opaque encrypted reasoning replay; once the transcript exceeds the small Host service cap it must fail closed before the next Provider request. The redacted local SSE record does not preserve actual encrypted-content byte lengths, so it cannot prove that ciphertext size *alone* caused this specific rejection. A separate offline fake OpenAI SSE test inserted a **12 KB fully completed and replayable reasoning value in the second task response** and reproduced the same failure at exactly two Model/Tool calls, before the third dispatch. This is a benchmark Host budget mismatch, not evidence of an OpenAI model-quality failure or a reason to suppress encrypted replay.

**Scope-limited correction:** The `evidence-40-v1` Host suite now explicitly uses `ContextPolicy.MaxInputTokens=32768`; the historical **two-case** suite remains at **8192**, and SDK/Context estimation and compaction fail-closed behavior are unchanged. `EffectiveInputLimit` still takes the smaller of the verified model capacity minus reserved output and the Host service cap. The fixed synthetic evidence dossier is still large enough to require Context Artifact archival and the original Oracle is unchanged. A red/green offline replay test now emits `response.output_item.added` (partial reasoning), `response.output_item.done` (12 KiB completed ciphertext) and a differently encrypted terminal reasoning projection, then completes all four Task Model calls and the real Agent/Tool/Context/recovery Oracle under the new quality limit. The outbound replay keeps the authoritative completed-done value, never the provisional added or different terminal value, while preserving the `1 attempted / 39 skipped` pilot boundary. A complementary 40 KiB signed/replayable reasoning fixture **still fails closed** with `context_budget_exceeded` after two task Model calls and no draft execution, proving the budget was not disabled. The new OpenAI quality dataset hash is **`sha256:1d57c9a8827816d63340f027a60bfdc92c63624e982232cb4f49ba2ff2bf3993`**; previous quality attempts had **`sha256:73424212f400c6226d6329e6ae5474bd84b81c6a35d5aaf964f117519c0aa970`**. ## Follow-up: PR #94 independent report-consistency audit and correction

A separate review of the immutable original PR Head `a79cc3d2d49ec1fee620218364a12b2f46b2677e` found a P1 cross-layer budget error: `validate_report()` treated `ContextPolicy.MaxInputTokens=32768` as a **minimum model input window**, although Go `EffectiveInputLimit` correctly uses `min(model capacity minus output reservation, service ceiling)`. Thus an admitted, successfully completed 16,384-token-capacity quality Pilot could create a report that `read_report()` rejects. The correction preserves the existing 8,192-input-token **fresh-run admission floor**, while using the smaller of that floor and the *recorded* Host ceiling when reopening historical reports. No SDK Context estimate or Go Model safety bound changes.

The same audit identified a pre-existing report protocol integrity gap (P2): independently manipulated Endpoint identity, summary duration/Usage subtotals, and false recovery booleans were accepted as valid success; Model/Tool diagnostic arrays could be deleted silently. Report admission now derives `endpointOrigin`/`endpointHash` from the exact configured endpoint bytes, requires per-sample diagnostic receipts, enforces known/missing Model calls and Tool execution totals, verifies completed successes have all seven recovery checks plus Run/Turn IDs, and recomputes duration nearest-ranks and aggregated token coverage from actual samples. Deliberately false, missing or internally contradictory evidence is rejected. A consistent report is **not** a signed/cryptographically attested Provider trace; mutually coordinated forged source values remain outside this report parser's trust guarantee.

Regression matrix: model windows 9,216 / 16,384 / 32,768 / 33,792 / 65,536 with a quality ceiling of 32,768, plus 200 seeded model-capacity/output-reservation combinations; historical ceiling 6,144; identical-origin/different-path and different-origin Endpoints; known-only/unknown-only/mixed Usage; pass/fail/recovery and missing receipts; pilot mode/case identity and summary mismatches. Python tests additionally run 450 fixed-seed state-machine mutation cases. The corrected local Python report suite passes **93 tests** (up from 87 on the original PR Head). The corrected local working tree has passed `make check` (including full Go tests/race/vet/lint, TS gates, evaluation smoke and release consumers) and a separate **93/93** Python report suite; `git diff --check` is clean. ### Post-push independent review: Unicode Endpoint identity

A review of the first replacement Head (`175db9a`) identified a narrow, real cross-language mismatch: Go `net/url.URL{Scheme, Host}.String()` percent-encodes non-ASCII authority bytes, while Python's new `endpoint_identity()` originally retained literal Unicode host characters. Thus a permitted URL such as `https://bücher.example/path` would be accepted at launch but fail to match the Go Start identity before preflight. Python also admitted percent-escaped DNS authorities that Go rejects at parse time. The final correction mirrors Go's origin escaping while preserving the SHA-256 hash of the original endpoint bytes; it rejects invalid authority escapes and retains bracketed IPv6 `%25` zone separators. Cross-language expected values were checked against independent Go `net/url` execution and added as permanent regression cases. This is confined to Host report admission, not a Provider/Kernel protocol change. The `175db9a` CI result must not be used as final-head evidence once this follow-up is pushed.
