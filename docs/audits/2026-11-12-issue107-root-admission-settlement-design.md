# Issue 107: bounded Root admission and settlement proposal

Status: proposal only; production implementation is not approved by this document. Baseline source 2545aa7b6eda95d193ecd549f29f1aecc387d108; B09 evidence 8dfcc8a6a647d1b3037514518d1987110bb74f35. Scope is the frozen Root Agent authority and unknown-outcome obligations, not a new scheduler or broad audit.

## Preserve the existing protocol
ExecutionLease remains native ownership; ModelInvocation remains model intent/receipt identity; ToolDispatch and ToolOutcomeVerifier remain tool unknown-outcome authority. An additional durable physical barrier must not replace these with Workflow settlement semantics. Existing quarantine revokes native authority and permits trusted repair; it is not an active-owner scope and cannot simply be reused.

## Atomic admission
Pure preparation and source freezing precede Create. Native Acquire follows Create. Before any arbitrary Host RunMiddleware, a single Store transaction must verify RunID, revision, nonterminal state, original OwnerID/LeaseID/Epoch and Store-time validity, then establish a durable scope bound to that original authority. Binding separately after a process-local check is insufficient. A narrow owned-physical-admission capability is preferable to changing existing child admission semantics.

Acquire/takeover and ApplyControl must inspect the same durable barrier before changing epoch or state. Active/Unknown survives lease TTL. Original owner renewal retains exact identity checks; an expired owner gets no extra send authority from the barrier. Legal nonnative configurations need a physical scope without pretending to have a lease. Missing required Store capability must fail before Create or callback, with explicit compatibility documentation.

## State and settlement
- Prepared: no callback has been entered; first-party admission/preflight failure may prove no effect.
- Active: original source/operation/attempt and authority durably admitted before callback.
- Unknown: callback may have acted but no authoritative result is durable. Resume does not enter Host, Generate, or dispatch again. TTL, retryable errors and ordinary cancellation are not no-effect proofs.
- Receipt committed / ACK lost: read original receipt and finish consumption/settlement without sending again.
- No-effect confirmed: only a trusted proof bound to the original attempt permits a new attempt.
- Settled: durable settlement and barrier retirement are idempotently recoverable; read state after ACK loss.

Host middleware requires an explicit trustworthy outcome contract. A nil return is not proof that arbitrary asynchronous work is settled; an error is not proof of no effect. This compatibility decision requires review before implementation. Without a receipt-query/settlement capability, an unknown Host outcome must remain blocked rather than fabricated as recoverable.

Model must persist dispatch uncertainty separately from a merely expired claim. Reuse original invocation ID, RequestHash, provider/binding fingerprint, attempt and ModelCompletionAuthority. A trusted, read-only ModelOutcomeVerifier analogous to ToolOutcomeVerifier may return an original authoritative receipt; public calls should select identity, never supply arbitrary proof. Completed receipts may be consumed without Generate. Also inspect and constrain the same-call retry logic in execution_policy.go so timeout cannot bypass unknown gating. Tool's current unknown behavior and exact-call reconciliation must remain intact.

### A. Data and atomic authority
Reuse physical-grant storage as an additional barrier, not as the Root execution/receipt protocol. Add immutable native binding (owner ID, lease ID, epoch, original admission source hash) to the grant representation and native tables. Old child/Workflow rows keep empty binding and existing interpretation; no guessed backfill or deletion of unresolved rows. A narrow OwnedPhysicalExecutionStore admission verifies kind=agent, Root identity, original revision and frozen source/checkpoint, permitted execution status, exact current native lease and Store-time expiry, and conflicting scopes in one transaction under existing lock order. All live ancestors remain protected by EA03. Ordinary child/Workflow Begin is unchanged and cannot forge the owned binding.

A first-party scoped Runtime carries both the exact lease and opaque physical write permit. The same Store transaction enforcing ApplyExecution checks revision, valid native bearer and matching scope; ordinary Apply cannot evade either fence. Control checks the scope before epoch revocation. Acquire rejects any takeover while an owned scope is active or unknown even after TTL. Release rejects until retirement. Renew only extends the same currently valid identity, never revives expiry or clears uncertainty. CheckExecution validates the native binding and remains a pre-dispatch check, not completion proof.

### B. Segment identity and settlement CAS
Use (RunID, grant ID, admission revision, owner ID, lease ID, epoch, admission source hash) as immutable segment identity. Current revision/state/checkpoint are additionally sealed into first-party completion proof. The scope starts before the first Host callback and lasts through all next calls and post-next middleware work. Mark is the durable whole-callback completion record, issued only after synchronous chain return plus no unresolved ModelInvocation/ToolDispatch/external/deferred physical work. Mark and Finish validate the same original identity and exact marked revision under Store lock/transaction. A repeated Mark of the same identity/revision and repeated Finish recovery must be deterministic, not a new dispatch authorization.

Begin ACK loss requires reading the same exact binding, never constructing a second scope. Mark ACK loss permits read-only proof inspection and Finish; Finish ACK loss permits absence verification. A receipt alone cannot prove an arbitrary Host callback completed after next. If callback completion was not durably recorded and cannot be authoritatively established, retain Unknown even when RunStatus looks terminal. Recovery must not execute middleware or acquire a new send-capable epoch merely to decide whether completion occurred. An expired owner may not write, renew or send using a surviving barrier. A recovery-only first-party settlement seam may retire already durable facts without handing out ordinary Apply authority.

### C. Default and externally supplied owner
After resolving ExecutionPolicy, nil RunExecution receives a unique Agent owner ID using Runtime.NewID and an internal lease duration covering max(Model timeout, complete safe Tool retry/backoff window) plus renewal margin, bounded by the existing 24-hour maximum with checked arithmetic. Invalid oversized policies fail construction rather than truncating safety windows. Explicit RunExecution retains its existing policy validation and precedence. Middleware itself may outlast timeout; expiry then stops native writes/sends but never retires its barrier.

Add a narrow first-party accessor for a Runtime's already-bound original lease. Validate RunID and Store-time authority; reuse it, do not reacquire or release a caller-owned lease. A freshly acquired segment owns its own release only after settled retirement. Missing required Store capability fails before Create. Preserve existing externally bound Run, deferred Prepare, empty-ID/default construction behavior with explicit tests rather than imposing an unreviewed new required parameter.

### D. Entry composition
Start: pure preparation and frozen source -> Create -> native ownership + atomic owned admission -> whole RunChain -> original Model/Tool interpreter -> whole-chain completion/Mark/Finish -> owned lease release. Prepare uses the same wrapper because it also invokes middleware even though its next path does not dispatch Model/Tool. Resume performs existing exact preflight then refuses unresolved original scope before any callback; remove duplicate inner ownership acquisition from continuePreparedRun. ResolveApproval and ResumeToolWait retain existing checkpoint/control identity and allowed-status semantics; do not force WaitingInput through a Running-only admission or weaken approval proof. Trusted Tool/Model outcome recovery may inspect/commit the exact original receipt through constrained recovery authority, then continuation is a separately admitted segment. Changes to child entry paths must preserve their original grant and parent provenance, never transfer an ancestor permit.

### E. Model uncertainty
Persist original invocation attempt dispatch state at the final guarded boundary before Generate. Crash after that CAS but before send is conservatively Unknown. Claim TTL/RetryAfter can advance only an undispatched attempt or a trusted original-attempt no-effect proof, never an ambiguous provider error. Completed/Consumed original receipts retain their existing request hash, binding and completion authority and may be consumed without Generate. The current policy layer does not itself loop Generate; it wraps timeout as retryable and agent invocation release/reclaim completes the replay path. Change both ends together. Retain modelPreDispatchDenied only where it actually proves this invocation never entered the provider. No full provider-query adapter project is required; absent trusted proof remains unknown. Any optional verifier must be trusted/read-only and exact original identity, not caller-supplied arbitrary response.

- Physical P1 begins at the atomic owned admission, not bare lease acquisition. A competing control may win between Acquire and admission; retain a P0 test proving zero callbacks, no second acquisition and no mutation of that winner. P1 then verifies rejection of independent Apply, lease-bound Apply without physical permit, Cancel, Acquire and Release. A ready signal does not clear dispatch, retire the scope, acquire a new owner or permit a send; original authoritative receipt is still required. Preserve legitimate pending-return semantics separately from unknown-error semantics.
