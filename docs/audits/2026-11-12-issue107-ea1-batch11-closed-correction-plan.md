## Proposed finite completion-receipt design (not yet approved or implemented)

Use the existing original Root scope, not a replacement authority. Instrument each actual callback layer with an unforgeable per-call nonce bound to original Run/grant/native owner+epoch/operation, input source hash and adapter version. Observe entry, every entered Next's return, and the adapter's own final return. Only explicitly trusted, audited, bounded first-party adapters can mint an opaque completion receipt for their own work. Context hydration/archive receipts bind the original checkpoint/ref and already committed artifact; SharedBudget receipts bind the original reservation, ledger version and the Agent's private Provider-no-send fact. No callback is rerun to manufacture a receipt.

Whole callback completion requires every participating layer's exact receipt, all entered Next calls returned, no unresolved physical intent, and original identity/source/current-revision CAS validation. Expiry does not authorize normal Apply or sending: only the existing immutable original callback-return recording channel may record the historical fact. Receipt ACK uncertainty, mismatch, unreturned layer or failed adapter cleanup leaves Unknown. Completion cannot be inferred from nil/error, zero provider calls, a Provider-only no-send proof, TTL or a clean-looking snapshot.

Ordinary arbitrary Run/Model middleware and unclassified preparer functions remain opaque. Their historical automatic-error-retry behavior is not transparently preserved by this proposal and must be documented. The held arbitrary middleware fixture must not be silently relabeled trusted: use an explicitly bounded test adapter with an auditable no-extra-effect implementation, retaining the opaque-middleware negative case. This limited design covers only the identified Context and Budget/no-send paths, with exact-source, duplicate/contradictory receipt, post-Next failure, expiry and no-replay negatives. It does not add provider queries, new effect execution, global error exemptions or mutable Hostfalse-to-true replacement.
