# Agent Runtime 0.1.0-beta.12

This release makes execution safety a Runtime-owned deployment concern so hosts
can remove low-level model/Tool/token/child-run budgets from product Role and
Environment resources. The beta.11 tags and archive remain immutable.

## Changes

- Bound direct Agent model and Tool calls with deployment-owned per-call timeout,
  bounded retry/backoff, panic containment, and per-Runner concurrency. Model
  retries preserve durable invocation identity; Tool retries remain opt-in for
  explicitly replay-safe failures.
- Add versioned Koanf bootstrap assembly for host-selected Kernel/Agent
  components, secret references, Agent hard limits, and model/Tool execution
  policy.
- Apply the same bounded external-call principles to Group Chat selector
  execution and respect Run deadlines across model, Tool, hosted-Tool, and
  selector calls.
- Add Runtime-owned hard-ceiling resolution. Per-Run and frozen Role limits may
  tighten an Agent Runner deployment policy but can no longer widen it.
- Add Harness execution policy for new Turns. When shared Budget middleware is
  composed, zero-config Turns freeze topology fuses of 32 descendant Runs and 8
  active execution slots while shared model/Tool/token ceilings remain unset.
  New Turns also freeze a delegation depth of 4 by default.
- Preserve structured budget-denial dimensions and surface stable Agent terminal
  error codes such as `agent.shared_llm_calls_budget`. Child-run exhaustion from
  the delegation Tool becomes recoverable model guidance and removes further
  delegation from that Agent Run instead of leaving phantom child topology.
- Keep provider-specific effort/task guidance outside Kernel. Hosts can continue
  using frozen `ModelOptions` without allowing model guidance to widen Runtime
  hard limits.

## Upgrade notes

1. Upgrade all nine Go modules to `v0.1.0-beta.12` and use
   `orz-i-agent-runtime-client-0.1.0-beta.12.tgz` from this GitHub prerelease.
   Beta packages are not published to npm.
2. Agent `Dependencies.Limits` is now an actual hard ceiling: nonzero
   `StartRequest.Limits` values can only tighten it. Hosts that previously used
   request-level limits to increase Runner limits must move the intended hard
   ceiling to Runner construction/bootstrap.
3. Harness hosts may set `Dependencies.Execution`. Zero values resolve to the
   SDK defaults. Turn `SharedBudget` and `DelegationPolicy.MaxDepth` can only
   tighten the resolved deployment policy.
4. A Harness without `BudgetMiddleware` remains valid and does not gain an
   implicit shared ledger. It still freezes the Runtime-owned delegation-depth
   default for new Turns. Supplying `SharedBudget` without Budget middleware is
   invalid as before.
5. Existing persisted Runs and Turns are not rewritten. The new Harness defaults
   apply only when a new Turn is created.
6. HTTP v1 and the TypeScript wire surface are unchanged in this release. The
   TypeScript archive version advances only to keep the coordinated Beta cohort.
7. Continue upgrading workers and SDK modules as one version cohort. Mixed
   beta.11/beta.12 workers are not covered by the compatibility gate; follow the
   forward-only procedure in the [integration contract](../integration-contract.md).

The release workflow must verify the complete root plus nine-module tag set and
pass `make check`, coverage, security, real PostgreSQL/Redis integration, and
the OpenTelemetry Collector gate before publishing the TypeScript archive.
