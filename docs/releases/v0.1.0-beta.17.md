# Agent Runtime 0.1.0-beta.17

Beta.17 hardens error handling across the durable Agent, Harness and HTTP adapters. It preserves verified model-failure causes without granting automatic retry authority, and keeps internal diagnostic text out of ordinary owner-facing API responses.

## Changes

- **Structured model failure codes.** Host model adapters may wrap an error with `model.NewClassifiedError(cause, code)` using a fixed allowlist of provider-neutral codes. `model.ClassifiedErrorCode` preserves the wrapped cause through `errors.Is/As`. Agent writes the stable code only when the model attempt becomes terminal, including after bounded retry exhaustion; otherwise historical generic outcomes and retry policy remain intact.
- **Ordinary Run and Harness responses.** Run snapshots, cancellation, Run Feed, event journal, Harness Turn, Invocation, Subtask, Harness Feed and Workbench return safe failure summaries and bounded codes instead of untrusted `ErrorDetail` text. The Kernel and Harness stores retain the original detail for separately authorized server-side investigation.
- **Workbench integrity.** SDK HTTP projections remove known diagnostic-only fields while preserving legitimate user-authored data and business failure objects under explicit result/input/tool-output contexts. After projection, Section, Topology and Workbench hashes reflect the visible payload rather than the previous internal content.
- **Workflow trace.** Public Workflow trace error codes are allowlisted; effect/provider errors cannot smuggle arbitrary request strings into `errorCode`.
- **Reviewed wire fixture.** `cancel.json` now returns the fixed safe cancellation summary rather than the supplied cancellation reason. The field shape and ordinary Run-owner authorization are unchanged.

## Compatibility and required host migration

1. Upgrade all nine SDK Go modules to **`v0.1.0-beta.17`** as one release cohort. Install the TypeScript client from the **`orz-i-agent-runtime-client-0.1.0-beta.17.tgz`** asset on this GitHub prerelease. No npm registry publication is performed.
2. Hosts that distinguish verified Gateway/Provider failures should call `model.NewClassifiedError` **only** with an evidence-based typed code, not Provider text. A code does not mean a model request or Tool effect is immediately safe to repeat. Respect existing durable attempt limits, call allowances, approvals and cancellation.
3. **HTTP behavior change:** consumers must not rely on raw `run.errorDetail`, Harness invocation/subtask error strings or Feed/Workbench free-text diagnostics for debugging. Use `errorCode` plus host-owned public recovery policy; route privileged investigation through separately authorized server-side diagnostics.
4. The SDK does not add a new admin/debug API, query parameter, role claim, retry engine, cost ledger or DB migration. Object ownership still grants only ordinary Run access. Arbitrary user-authored output/tool content remains a separate explicitly authorized data channel; field filtering is not a universal credential-scanning/DLP guarantee.
5. Existing persisted Runs and Workflow states are not rewritten. If an application operates mixed prerelease workers, drain and update the entire SDK cohort before running new workloads. Rollback requires ordinary worker quiescence; rolling older workers against new persisted state is not an established compatibility promise.

## Evidence and limits

The SDK candidate has deterministic Go tests for typed causes and bounded retries, HTTP route/fixture and cross-tenant security regressions, SSR-independent diagnostic projections, Workbench hash consistency, Race tests and packed TypeScript consumers. Release acceptance requires full `make beta`, protected PR checks, the immutable ten-tag set and the GitHub release workflow. These checks do **not** establish real MiniMax/Gateway error-injection compatibility or actual production RBAC for a future privileged diagnostic endpoint.

Gaoge should **not** adopt an untagged SDK candidate. Its P2 host branch must pin this published Beta, connect verified Text Model errors to `model.NewClassifiedError`, and complete its own Conversation/Workbench/SDK-HTTP tests before separate host merge approval.
