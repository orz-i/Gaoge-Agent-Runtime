# Agent Runtime 0.1.0-beta.10

This release gives the changes after `v0.1.0-beta.9` their own immutable version
boundary. It includes Runtime changes through `4ebb17c740b585d62110300d266143a58a2cdb9b`;
the beta.9 tags and archive remain unchanged.

## Changes

- Group Chat supports directed speakers, durable selector routing, visible-speaker
  handoff, and visible A2A speakers. Speaker identity, execution configuration,
  remote binding revision, selection state, and child execution identities are
  frozen for recovery. A2A remote input/auth waits can resume using the stored
  binding and expected revision.
- Routed roles share the delegation policy boundary. Manual subtask spawning
  uses the frozen roles, delegation depth, and shared Turn budget. HTTP and
  TypeScript expose the delegation availability and subtask spawn operation.
- Hosted-tool stream feed events carry only call ID, tool key, and status;
  argument/result bodies are omitted from these lifecycle events.
- Failed top-level capability starts retain the original cause in Turn and
  Invocation state, including after reload. Missing hosted-tool errors include
  the requested tool key while retaining the wrapped tool-not-found error.
- Clean-consumer tests cover all eight Go modules and the packed TypeScript
  entrypoint. Shared fixtures check Go HTTP serialization, OpenAPI, and TypeScript
  declarations. Real-engine tests cover populated-store migration reapplication
  and recovery behavior.

## Upgrade notes

1. Upgrade all consumed Go modules to `v0.1.0-beta.10` and use
   `orz-i-agent-runtime-client-0.1.0-beta.10.tgz` from this GitHub prerelease.
   Beta packages are not published to npm. A source-consuming host must pin its
   SDK submodule to the commit of the root and all eight module tags, and align
   its workspace dependency and boundary checks to the same version.
2. Hosts enabling Group Chat must compose the Group Chat runner, continuation
   registration, speaker resolver, and the selected routing policy. Supply
   authorized participant identities and frozen role/speaker snapshots. Visible
   A2A speakers require the frozen remote binding and revision-aware wait resume
   path; a role ID alone is not a visible author identity.
3. `RuntimeKind` is now a feature-owned string rather than a closed four-value
   TypeScript union; handle unknown feature kinds. `HarnessExecutionClass` adds
   `group_chat`, snapshots may contain delegation metadata, and subtasks may
   include `runID`. Checkpoint/Result OpenAPI schemas describe existing emitted
   fields. Review exhaustive switches and feed consumers accordingly.
4. Consumers of hosted-tool stream events must not expect raw arguments/results
   in the feed. Error text now preserves capability startup causes and identifies
   missing hosted tools; use typed/wrapped errors rather than exact old strings.
5. No new SQL migration or replacement of existing Go constructor signatures is
   introduced. New Group Chat state and role/delegation snapshot fields are
   persisted execution data. Upgrade workers as one version cohort, preserve
   frozen snapshots, and follow the forward-only migration policy in the
   [integration contract](../integration-contract.md). Current-version recovery
   tests do not establish downgrade or mixed-version-worker compatibility.

The release workflow must verify the complete tag set and pass `make check` plus
real PostgreSQL/Redis integration before publishing the TypeScript archive.
