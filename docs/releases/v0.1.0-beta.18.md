# Agent Runtime 0.1.0-beta.18

An incorrect Context artifact ID now returns `context_artifact.not_found` as a
correctable Tool result, allowing the same Agent Run to retry with the exact ID
from its checkpoint. Durable caller ownership is resolved first; cross-scope
access, missing ownership and non-not-found store failures remain denied.

Oversized archives report `ArtifactPayloadLimitError` with content-free
`PayloadBytes` and `LimitBytes` facts. `errors.Is` continues to match
`ErrInvalidInput` and additionally matches `ErrArtifactPayloadTooLarge`. The
4 MiB durable ceiling and lossless, fail-closed archival behavior are unchanged.

Hosts may classify those typed failures as `context.artifact_payload_too_large`
and input-budget failures as `context.input_budget_exceeded` using
`model.NewClassifiedError`. SDK HTTP surfaces retain these exact registered codes
and static recovery summaries, while internal diagnostic details stay private.
No error-text parsing or automatic retry is introduced.

A zero native count for a complete sampling request now uses the conservative
fallback and is recorded as `estimated`, rather than an `exact` zero count.
Hosts should supply their existing protocol-aware tokenizer for pure-text
requests too; byte-based fallback remains authoritative when counting is unavailable.

This cohort also includes the accepted Windows shell-free release command fix
and Node toolchain dependency updates after Beta.17. Upgrade all nine Go modules
and the TypeScript client together to `v0.1.0-beta.18`. The TypeScript archive is
`orz-i-agent-runtime-client-0.1.0-beta.18.tgz` on this GitHub prerelease; npm
publication remains disabled. No SQL migration or HTTP response shape changes
are required. Hosts retaining older public error registries must add the two
Context codes to expose the specific recovery messages.
