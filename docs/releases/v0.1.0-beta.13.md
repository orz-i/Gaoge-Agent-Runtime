# Agent Runtime 0.1.0-beta.13

This coordinated Beta release adds Runtime-owned Tool Discovery and scoped
model-hosted Tool grants. The `beta.12` release and all its annotated tags
remain immutable.

## Changes

- Add read-only, bounded local/MCP Tool Search in the direct Agent Runner.
  Candidate keys and Schema SHA-256 fingerprints are frozen at Run creation;
  only already-authorized definitions can be discovered and loaded. Loaded
  definitions and sanitized search receipts persist through a single Kernel
  revision CAS for retry and Resume.
- Add deterministic SDK lexical search against authorized Tool definitions,
  with stable key ordering, up to five results per search and a 256-candidate
  SDK ceiling. Smaller sets stay eager. This does **not** implement
  OpenAI/Anthropic provider-native Tool Search.
- Add `InitialToolKeys` to distinguish local Tools made visible on the
  first model request from mandatory `RequiredToolKeys`. The Harness/Handoff
  retain first-party delegation and granted context-artifact read Tools across
  parent/child invocation boundaries without forcing a call.
- Add versioned, model-pinned Role-scoped Hosted Tool grants: a child may
  receive a previously approved Hosted Tool without granting it to the
  parent or siblings. Unpinned roles and changed/disabled/missing Hosted
  definitions are rejected.
- Validate frozen Tool definitions, Hosted Tool payload/version and loaded
  grant membership before business Tool execution and on every physical
  Provider retry, including after model concurrency admission. Invalid
  requests fail closed as `agent.discovery_invalid`.
- Restore official Go MCP Streamable HTTP SDK protocol negotiation for both
  modern and legacy initialization/connection-scoped sessions, without
  changing the Host's authentication and timeout controls.
- Bound Tool Search allocation capacities to authorized collection sizes,
  and canonically sort frozen initial/loaded Tool keys for durable state
  validation.

## Upgrade notes

1. Upgrade all nine Go modules to `v0.1.0-beta.13` together. Use
   `orz-i-agent-runtime-client-0.1.0-beta.13.tgz` attached to this GitHub
   prerelease. Beta does not publish to the npm registry.
2. Agent `Dependencies.ToolDiscovery` is a new optional read-only search
   port. Deployments may compose `agent.LexicalToolDiscovery{}` for
   authorized local/MCP tools. Without composition, existing Eager mode
   remains the default; no new authorization is created.
3. Agent `StartRequest.InitialToolKeys` specifies **already-authorized
   local keys** to expose initially; this is not an additional grant and
   does not require them to be invoked. A Host/Harness composing this feature
   must supply the set from the frozen granted Tool list.
4. `agent.HostedToolGrant`, Harness `RoleSnapshot.HostedToolGrants` and
   Handoff frozen `InitialToolKeys` add new durable Run/Invocation fields.
   A Hosted role grant requires an explicit pinned role model and a matching
   current catalog `DefinitionVersion`. Hosts must not infer a grant from
   a model prefix or parent Tool selection.
5. Changing/revoking an already frozen Tool may now fail a pending/retrying
   Run before another Provider request. Consumers should treat
   `agent.discovery_invalid` as a terminal policy/definition mismatch
   requiring a new, reauthorized Run, not as an automatic retry hint.
6. Existing beta.12 persisted Runs/Turns are not migrated here. No mixed
   beta.12/beta.13 worker or durable request continuation is validated;
   follow the forward-only deployment procedure and upgrade the active
   SDK modules/workers together.
7. HTTP v1 and the TypeScript client wire API are not expanded by the local
   Tool Discovery capability. The TypeScript version advances to keep the
   coordinated release cohort.
8. Tool Search synthetic request-size measurements are not measured Provider
   Token savings, task accuracy or live MiniMax web-search compatibility.
   Those require separate, appropriately authorized integration validation.

The release workflow verifies the root plus nine annotated module tags
against one immutable accepted commit, then runs SDK check, coverage,
security, real PostgreSQL/Redis integration and OpenTelemetry Collector
checks before attaching the TypeScript client archive.
