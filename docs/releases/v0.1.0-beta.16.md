# Agent Runtime 0.1.0-beta.16

Beta.16 fixes soft-segment guidance and Workflow child context ownership found while validating a consuming host with MiniMax M3.1 Flash Preview.

## Problem and behavior

The guidance near a renewable execution-segment boundary could cause a model to claim that its hard limit or context window was exhausted and finish before Runtime renewed the allowance. The guidance now identifies the soft boundary explicitly, asks the model to continue authorized unfinished work, and reserves budget-stop claims for an actual Runtime pause or denial. Hard ceilings, progress checks, renewal counters and owner-authorized manual continuation are unchanged.

A Workflow executor can start a child synchronously. Registering its relation after startup is too late when Harness middleware resolves parent policy during that startup. `workflow.EffectRequest.OwnerNodeID` now exposes the stable relation owner for the current effect attempt. Hosts must register parent/child ownership with this value before starting a child that resolves parent policy. Retry attempts and fan-out effects retain distinct stable owners.

`harness.WithoutContextWindow` now carries an explicit hydration exclusion. Context middleware honors it, allowing a host to preserve an isolated child task's immutable input across startup, approval and recovery.

## Host migration and compatibility

1. Upgrade all nine Go modules together to `v0.1.0-beta.16`. The TypeScript client archive is `orz-i-agent-runtime-client-0.1.0-beta.16.tgz` on the GitHub prerelease; Beta packages are not published to npm.
2. `OwnerNodeID` is an additive Go request field. Use it when registering Workflow child ownership before child startup; `NodeID` continues to identify the definition node. An executor that does not create children needs no change.
3. Hosts opting a Workflow child out of conversational context must apply `WithoutContextWindow` before Harness context hydration on each execution entry, including approval and restart recovery.
4. HTTP v1, TypeScript API, persistence schemas and budget limits do not change. Coordinate worker upgrades for active Workflow retries so all workers use the same effect-owner semantics.

## Verification

The host validation used the configured MiniMax M3.1 Flash Preview provider and a controlled read-only MCP fixture, because the anonymous AnySearch service has no availability guarantee. Durable Runtime records confirmed two automatic model renewals before the 32-call hard ceiling, rejection before a 65th Tool dispatch at the 64-call ceiling, same-Run manual continuation, and recovery at ordinary approval, budget pause and Workflow child approval without replaying completed Tool work.

The SDK release requires the existing full `make beta` gate, protected-branch PR checks and the tagged release workflow. Verify that the root tag and all nine module tags point to the accepted commit, and that the packed TypeScript archive is available before adopting the pin. Host validation does not establish compatibility with every provider or saturate the model's context window.
