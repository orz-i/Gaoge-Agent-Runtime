# Agent Runtime 0.1.0-beta.14

This coordinated Beta introduces **explicit, durable call-allowance pauses** for direct Agent Runs. It does **not** remove deployment-owned absolute ceilings or silently enable automatic execution beyond them.

## Changes

- Add nonterminal `paused_budget` to Kernel Run, Harness Turn and Invocation; persist an Agent-owned cumulative call allowance separately from frozen model/Tool hard ceilings. No allowance configured means the prior beta.13 behavior remains.
- Before a new logical model call or the next Tool in a pending batch, pause if the separately frozen allowance is exhausted. Persist the existing Run ID, transcript, invocation receipts, Tool IDs and settled results.
- Add `agent.Runner.GrantCallAllowance` with private revision-based Kernel CAS and a durable resumption wakeup; a grant can only expand the exhausted dimension up to its frozen absolute model/Tool ceiling.
- Harness adds an owner-scoped direct top-level Agent grant. HTTP `POST /harness/turns/{turnID}/allowance` accepts `expectedTurnRevision` and either `modelCalls` or `toolCalls` (positive increment), and validates owner session identity. Requests for another tenant return the same 404 response as missing Turns. Strict JSON rejects unexpected limit-override fields; stale/duplicate grants conflict.
- Explicitly retain a paused child as *pending* in Handoff/Workflow, prevent continuation workers from waking a paused Run without a grant, and project paused status through Turn feed.
- Update canonical OpenAPI v1 endpoint/status/stream contract and the TypeScript SDK, with public-schema regression tests, SQLite-backed GORM state/CAS tests, and concurrent grant-race coverage.

## Upgrade notes

1. Upgrade **all nine Go modules** to `v0.1.0-beta.14` together. Install the TypeScript archive `orz-i-agent-runtime-client-0.1.0-beta.14.tgz` from this prerelease; no npm registry publication.
2. `agent.StartRequest.CallAllowance` and `harness.StartRequest.CallAllowance` are optional deployment/host-composed controls. Without a positive initial segment allowance, the old model/Tool hard-ceiling failure path is unchanged.
3. `paused_budget` is **not terminal** and is distinct from approval waiting. Consumers that switch exhaustively on Run/Turn/Invocation statuses need a new case, and should display the exhausted dimension; a paused Run never automatically resumes. A successful grant returns the same Turn in `running` state, retaining its private Agent identity.
4. Grant increments are constrained by the *same frozen hard ceiling* (e.g. Gaoge P0 32 model / 64 Tool calls). A grant cannot renew a Run that already reached its hard ceiling. Automatic segments and future absolute-guard policies belong to later releases.
5. Public grant requires the **Harness Turn revision**; the private Agent Run revision/ID are never accepted by this endpoint. Treat 400 as malformed or unsafe increment, 404 as missing/unauthorized Turn, and 409 as stale or otherwise ineligible Turn.
6. Existing beta.13 persisted Runs and Turns are not rewritten. Terminal failed Runs are **not** revived or migrated to `paused_budget`. No mixed beta.13/beta.14 worker or durable continuation compatibility has been validated; upgrade all workers/modules together.
7. These unit, concurrency, schema and adapter tests do not establish live-provider pricing, true cross-process production PostgreSQL recovery or a Gaoge Chat UI. Gaoge host integration must separately opt in, authorize and test the pause-and-continue surface.

## Release gate

The workflow must verify the root and all nine Go module tags resolve to one immutable commit; run `make beta` (including security, coverage, live PostgreSQL/Redis and OpenTelemetry Collector gates), test clean Go and packed TypeScript consumers, and attach the TypeScript archive and these release notes to a GitHub prerelease. Beta versions must never publish to npm.
