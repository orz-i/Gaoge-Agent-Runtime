## v0.1.0-beta.6 Release Notes

### Feature

- Durable continuation now projects committed wakeups through the transition outbox, with a generic `run_ready` fallback for autonomous feature progress.
- Agent model calls and PlanExecute planner calls now use durable invocation records with stable `InvocationID`, execution claims/leases, provider `ResponseID`, and usage receipts.
- Shared budget and observability vocabularies are available without moving provider or telemetry SDK dependencies into the Kernel.

### Optimization / Contract hard cut

- Snapshot loading and event-journal reads are separate contracts; snapshots expose `eventHead` instead of embedding events.
- HTTP shared composition now requires explicit Run loading and object-level authorization dependencies.
- Agent budget projection lives under `View.Budget`; PlanExecute planners return `PlannerResponse`; Workbench accepts separate Run and Event sources.
- PostgreSQL transition persistence retains wakeup metadata, and real PostgreSQL integration coverage verifies aggregate loading remains independent of a 100,000-event history.

### Fixed

- Crash recovery gaps across Agent, Workflow, PlanExecute, and Team autonomous progress are closed with durable wakeup/relation/invocation state.
- Compose startup rollback uses a detached bounded cleanup context; failed rollback poisons the application instead of permitting an unsafe retry.

### Upgrade notes

- This Beta is a hard cut. Upgrade all Go modules together to `v0.1.0-beta.6` and update host adapters for the new Planner, continuation outbox, HTTP Shared, Workbench, Agent budget, and snapshot/event contracts. No compatibility bridge is provided.
- Keep Runtime `InvocationID` distinct from host request identity. Map it to provider idempotency/retrieval facilities only when that provider contract is known and reviewed.
- TypeScript remains distributed only as the `.tgz` attached to this GitHub prerelease. There is no npm registry publication and no `NPM_TOKEN` requirement before stable.

## v0.1.0-beta.6 中文版本

### Feature

- durable continuation 现在通过 transition outbox 投影已提交 wakeup，并提供通用 `run_ready` fallback，确保各 Feature 的自主推进具备恢复来源。
- Agent 模型调用与 PlanExecute Planner 调用新增持久化 invocation 状态，使用稳定 `InvocationID`、执行 claim/lease、provider `ResponseID` 与 usage receipt。
- 增加共享 Budget 与 Observability 词汇层，同时继续禁止 Provider SDK 与遥测 SDK 进入 Kernel。

### Optimization / Contract hard cut

- Snapshot aggregate 与 Event Journal 正式拆分；Snapshot 仅暴露 `eventHead`，事件通过独立 journal 接口读取。
- HTTP Shared composition 现在显式要求 RunLoader 与对象级 RunAuthorizer。
- Agent 预算投影统一到 `View.Budget`；PlanExecute Planner 返回 `PlannerResponse`；Workbench 显式接收 Run/Event 两类 source。
- PostgreSQL transition persistence 保留 wakeup metadata，并使用真实 PostgreSQL 100,000-event history 验证 aggregate load 不依赖 event journal 扫描。

### Fixed

- 收口 Agent、Workflow、PlanExecute、Team 自主推进过程中的 crash recovery 缺口。
- Compose Start rollback 改用独立有界 cleanup context；若 rollback 失败则 poison-close，禁止在资源状态未知时重试。

### Upgrade notes

- 本 Beta 为硬切版本。全部 Go modules 需同步升级到 `v0.1.0-beta.6`，宿主需同步适配 Planner、continuation outbox、HTTP Shared、Workbench、Agent Budget 与 Snapshot/Event 新合同，不提供兼容桥。
- Runtime `InvocationID` 必须与宿主 RequestID 分离；仅在 provider 已验证支持幂等或检索语义时映射使用。
- TypeScript 仍只通过 GitHub prerelease 的 `.tgz` 附件分发；stable 之前不发布 npm registry，也不需要 `NPM_TOKEN`。
