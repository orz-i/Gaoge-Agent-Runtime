# Agent Runtime 0.1.0-beta.22

This Beta is a corrective release for durable external Tool waits introduced in beta.20
and adopted by hosts with beta.21. A legal concurrent Run revision change could
previously make a deadline or result-ready continuation falsely succeed while
the Agent remained waiting, causing the queue Worker to acknowledge and lose the
only wakeup. Beta.22 removes that failure mode.

## Fixed

- Generation-aware Continuation now retries against the latest Run revision
  after an optimistic concurrency conflict. It rechecks the durable wait
  generation on every attempt and will not acknowledge a still-unresolved
  wakeup.
- If contention persists beyond eight local attempts, the existing durable
  queue Worker NACKs the delivery for bounded redelivery instead of ACKing it.
  Once contention clears, the original immutable generation can resume safely.
- Terminal/consumed/obsolete generations remain idempotent, and ordinary
  scheduled waits plus non-generation child-terminal continuations retain their
  previous execution semantics.

## Upgrade and compatibility

Upgrade **all nine Go modules** and the TypeScript client together to
`v0.1.0-beta.22`. The TypeScript prerelease archive is
`orz-i-agent-runtime-client-0.1.0-beta.22.tgz` attached to the GitHub Release;
the Beta is **not** published to the npm registry.

This fix makes no HTTP wire, TypeScript public DTO, persisted wait schema or
SQL migration change relative to beta.21. Existing typed waits can upgrade
forward; do not downgrade a Run storing typed waits to an SDK predating
beta.20. Browser execution still requires a host-owned durable receipt/outbox
and authorization boundary. Gaoge PR #32 must atomically update its SDK
gitlink, Go/TypeScript workspace and lockfile references, then complete
host-side review. This release does not add production browser claim/receipt
endpoints or server-side execution fallback.

The published beta.21 tags remain immutable. Verify the complete root + nine
module annotated tag cohort and the GitHub Release archive against the same
accepted `main` commit before considering downstream adoption.

## Validation criteria

The release is acceptable only after the frozen-lockfile install, complete
`make beta` gate (including coverage, security, real PostgreSQL 16 / Redis 8
and OpenTelemetry Collector), protected release PR review and required GitHub
checks. Additional deterministic regression tests cover deadline and
result-ready CAS conflicts, one-time tool consumption, exhaustion to NACK,
queue redelivery and stale/terminal generation no-ops. No production browser
deployment or paid model call is claimed.
