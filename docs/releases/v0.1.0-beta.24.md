# Agent Runtime v0.1.0-beta.24 — architecture hard-cut candidate

**Status: unreleased.** Do not install the candidate Go modules from remote
tags before the reviewed cohort is published. Beta.23 remains immutable.

## Changes

- **OpenAI/Anthropic required Tool response hard cut:** Both unary and SSE
  adapters now verify a forced local Tool request actually returns a
  decoded Tool call; text-only final results from nonconforming gateways
  fail closed without a successful terminal SSE receipt. If the completed
  response includes valid cumulative Usage, the existing typed
  `ResponseRejectedError` retains original ResponseID/Usage so Agent can
  account and consume that paid ModelInvocation exactly once (failure code
  `model.post_generation_failed`); unknown/invalid Usage never fabricates
  a completed receipt. In OpenAI phased output, a refusal in commentary
  still sets the global safety flag but cannot authorize an ordinary
  `final_answer` without the required Tool; only a terminal refusal-only
  message can waive Tool execution, and only with assistant role and
  completed status when those optional fields are explicitly present.
  Foreign roles, unfinished status and explicit null/empty values cannot
  confer that exception; omitted legacy fields remain supported.
  OpenAI `function_call` items must also be complete before entering a
  local Tool execution intent, independent of whether a Tool was required.
  Explicit unfinished/invalid item statuses reject the entire candidate,
  with no executable arguments/replay or SSE success; trusted cumulative
  Usage is preserved as a minimal billed rejection receipt even if the
  unfinished arguments are malformed. A subsequent P1 ledger correction
  also covers **completed** Tool items with malformed JSON/identifiers:
  OpenAI and Anthropic preserve only proven final
  ResponseID/Usage as a rejected paid completion (including Anthropic SSE
  final block reconstruction), with zero executable Tools/replay and no
  terminal SSE success. A follow-up OpenAI P1 repair also consumes a known
  completed response when a physically valid Tool item is mixed with an
  incompatible final/refusal or unsupported sibling item, or replay exceeds
  bounds. Its sanitized rejection retains only the verified ResponseID/Usage;
  absent/invalid Usage is not invented, and missing encrypted reasoning
  evidence keeps its existing failure class. The next independent P1
  correction covers Anthropic completed messages with a physical `tool_use`
  and an invalid sibling content block (including unsupported rich text and
  missing signed Thinking evidence), regardless of block ordering. It also
  preserves verified cumulative Usage across post-completion SSE reconstruction
  and Tool replay failures, without accepting partial Tool execution or
  inventing completion for unknown Usage. A further Anthropic SSE P1 fix
  also handles rich cited text or unsupported content encountered at
  `content_block_start`: mark semantic rejection, safely drain bounded
  protocol frames, and account the paid Tool-bearing invocation only on a
  valid final `message_stop` and verified cumulative Usage. No rejected
  content/deltas or ToolCalls become authorized, and truncated/malformed
  streams (including noncontiguous block indices) still cannot mint
  receipts. The next independent P1/P2 fix also accounts completed
  **Tool-free unsupported content** when Tool use was mandatory, and
  sanitizes otherwise-valid rejected text to ResponseID/Usage only: no
  rejected text or phase replay survives in a durable ModelInvocation.
  Unknown final Usage, incomplete replies and malformed SSE retain their
  original fail-closed classification. A further independent SSE phase P1
  prevents a `tool_use` block from arriving after `message_delta`, rejects
  out-of-order/overlapping/missing-index Tool blocks and contradictory or
  decreasing cumulative final deltas; real Agent integration proves zero
  Tool side effects for invalid late SSE frames. Valid multiple final
  `message_delta` usage updates remain supported. The next independent P1
  review also binds **outer provider resource identity** before any local
  Tool authorization: OpenAI requires `object="response"`; Anthropic
  requires `type="message"`, `role="assistant"`, including at SSE
  `message_start`. Foreign, absent, null or malformed owner fields cannot
  mint Tool intents, replay or final completion receipts. Offline unary/SSE
  and Agent/Kernel side-effect regressions were added, and simplified
  Mock envelopes were updated to the provider contract rather than kept
  as a compatibility path. An additional P1 fix enforces explicit assistant
  role and completed status for **every** OpenAI output `message`, including
  unphased messages mixed with a valid local Tool call. Foreign roles and
  unfinished/null/empty statuses reject the whole batch, retaining only
  validated ID/Usage as billed rejection evidence. The old behavior could
  execute a Tool Handler once on a malformed sibling; public Agent/Kernel
  regressions now prove zero effects. A subsequent independently reproduced
  P1 also fences whitespace-only or padded physical local Tool Call IDs in
  both adapters: Agent formerly trimmed/replaced the ID and then executed the
  Tool. Provider rejects the Tool with no effects, preserving only verified
  final ResponseID/Usage as a minimal paid rejection for Unary/SSE. The same
  exact-ID rule protects signed ProviderReplay; no compatibility rewrite is
  introduced. A further independent P1 closes OpenAI SSE completion-evidence
  substitution: observed `response.output_item.done` Tool/Message items must
  agree with the final `response.completed` on status, identity, content and
  absolute output index, or the stream fails without Tool execution or a
  fabricated billing receipt. Existing complete Reasoning evidence and
  final-only responses remain supported; Agent→SSE→Kernel tests prove zero
  effects under contradictory events. Explicit terminal safety refusals,
  non-forced text and valid Tool results continue to work. No new wire or
  persistence state, DB migration or adapter compatibility fallback.
  Offline HTTP/SSE and Agent integration tests cover the negative and
  positive paths; no new live Provider compatibility claim.
  See [Provider Tool result audit](../audits/2026-11-02-provider-required-tool-response-hardcut.md).

- **Round 3 root output and physical-owner provenance (P1 hard cut):**
  Child `RefreshInvocation` / `ResumeInvocation` cannot publish their
  physical results as the parent Turn `Snapshot.Output`. For all native
  root status/Item transitions (including failure/cancellation without a
  Result), terminal Host-output ACK and Agent `ResumeTurn`, the actual
  Kernel Run must match frozen Run ID, Kind, Actor, Thread, Goal and
  Attempt-bound RequestID. Root Cancel and top-level Feature Start replay
  check this before physical Cancel/Resume; mismatched Runs cannot be
  cancelled, resumed or used to write root lifecycle facts. Native child
  Invocations additionally verify their bound root/ancestor Attempts and
  frozen Kind, Actor, Thread, Goal and Attempt-specific RequestID before
  physical dispatch, native Resume or status/Artifact projection. Remote
  Handoff children retain fixed ChildRunner proof; proven no-Run child
  cancellation retains the original explicit no-effect path. Local
  native Invocation and RunRelation checks also require frozen physical
  owner proof before Kernel Cancel or Run-backed Subtask Goal/status/Result
  projection, blocking foreign same-ID Run cancellation and cross-tenant
  Subtask disclosure. `KindCapability` relations must also bind the
  original child Attempt's OwnerNodeID and the frozen root's ParentRunID
  to the same Turn before any read or cancellation; `CancelSubtask`
  verifies this before minting an intent. Application roots never read
  Kernel results, even if a foreign Run
  occupies the same ID. Their original Host `OutputRefs` remain authoritative.
  Result-free historical read-only state is still inspectable; no-Run
  admission-rejected recovery remains supported. Tests cover wrong tenant,
  Kind, Thread, Goal, result-free state and Host ACK, valid owner and retry
  recovery. No new Store, API, DB schema or compatibility adapter. See
  [round 3 audit](../audits/2026-11-01-root-output-provenance-governance.md).

- **Round 2 Invocation lifecycle terminal authority:** The shared Harness
  projection rejects stale child Runtime snapshots that attempt to change a
  terminal Invocation to another status. Memory and SQL `Store.UpdateInvocation`
  enforce the same rule atomically with Revision CAS. Same-terminal metadata
  reconciliation remains possible, and explicit `RetryInvocation` retains its
  separate Attempt/Run-ID rotation. Custom Store adapters must implement the
  stricter terminal CAS. New regression tests cover terminal rollback,
  original-Item immutability, SQL parity and legitimate retry recovery.
  No Kernel status changes, new persistence fields, DDL or compatibility shim.
  See [breaking-change ledger](../breaking-changes.md).

- **Minimal single-Agent composition (round 1):** A plain Agent needs only
  Kernel + Agent; optional text Session composition uses the same Agent, one
  Harness Store, a Context Manager and pre-commit Context projection. The
  Harness `Dependencies.Clock` may now be nil and uses the system clock for
  Harness record timestamps; an explicitly injected Clock remains supported.
  This does not alter the Store's authoritative execution lease timing, install
  a Context manager automatically, or relax Agent Tool receipts. Add executable
  small Session and quickstart output regression tests, including a delayed
  historical `Load` after Host history advances and fail-closed rejection of
  a changed old `Prompt` (without an extra model call). No extra public
  factories, modes, schema changes or compatibility bridges.

- **Agent loop / Host intent boundary:** Remove the misleading internal
  `Direct Agent` helper names and present new Agent journal events as
  `Agent loop started/completed`, retaining event types and original frozen
  execution identities. The SDK has no `IntentRouter`, `PrepareIntent`,
  `DirectMode` or generic `Start`; Hosts choose explicit `Start*Turn`
  entries. `PrepareRun` still provides deferred Agent execution;
  `PrepareModelRequest` remains the single pre-commit Model request
  projection, not a user intent router. Renamed benchmark identity retains
  unchanged reviewed baseline values. No extra route or compatibility shim.
  See [ADR 0016](../adr/0016-agent-loop-and-intent-boundary.md).

- **PR #82 native Subworkflow pre-dispatch relation ownership:** Registered
  built-in Subworkflows persist the stable parent/child RunRelation before
  physically creating, resuming or observing a child. The original frozen
  Effect owner and fan-out flag (`EffectRequest.Mapped`) are preserved across
  retry and replay. A failed relation write prevents child creation; a
  committed write with lost acknowledgement remains explicitly unresolved
  during cancellation rather than falsely confirming the child stopped.
  Memory and real PostgreSQL tests verify pre-dispatch ordering, failure,
  idempotent replay and fresh-connection recovery. Orphans from earlier
  candidate code require explicit inspection; no schema migration or
  compatibility bridge is introduced.

- **PR #82 original composite cancellation route proof:** Built-in Team,
  GroupChat and Workflow must execute on the exact Kernel bound to Harness;
  a foreign native Runtime is rejected during `NewRunner` composition even
  when the relation registry is shared. Host Feature wrappers now need both
  `OwnsKernelRuntime` and `RecordsRelationsTo` to authorize local cancellation;
  omitting either proof fails closed rather than borrowing a local Run or
  claiming that an empty index proves no children. Unknown cleanup keeps its
  durable cancellation intent. Migrate Host wrappers to explicitly attest
  their original fixed route and exact recorder, or reconcile their physical
  results through the external execution owner. No new remote Cancel adapter,
  schema migration, compatibility bridge or version bump for unreleased data.

- **PR #82 composite cancellation relation coverage:** A Team, GroupChat or
  Workflow with an existing Harness-owned physical Run needs the same indexed
  relation source used by its original native Feature. Without the source, or
  when native Feature and Harness recorders differ, an empty child scan is
  never authoritative: cancellation returns `ErrRuntimeCancellationUnverified`
  and retains any already-admitted cancellation intent, instead of confirming
  that a still-running remote member was stopped. This applies to Running and
  terminal parent Runs; the original Invocation class prevents a colliding
  foreign Run from lending false ownership. Hosts must wire the same durable
  recorder to both native Feature and Harness, and reconcile existing
  unindexed work before considering it cancelled. No schema version, Store
  interface, remote Cancel RPC or migration bridge is added.

- **PR #82 Feature route and receipt proof:** Raw Team/GroupChat/Workflow
  descendants require their owning Feature's fixed same-Kernel route and
  persisted task evidence before local observation, approval or cancellation.
  Same-ID Runs and unrelated native Invocations do not authorize an edge.
  Custom/dynamic/remote Feature routes without this proof remain unverified;
  retain their cancellation intent and reconcile through the actual owner,
  rather than introducing a local fallback. Delegation Tool read-only recovery
  and autonomous waits require the same frozen ownership. Built-in subworkflow
  recovery rejects mismatched immutable definition/input/origin before Resume
  or accepting a Create-conflict result. Handoff ancestor liveness also
  requires owned observation; unrelated Handoff no-effect grants cannot settle
  raw Feature cleanup. Physical Subtask approvals require the exact original
  fixed first-party Agent, not a root wrapper or another same-Kernel Agent;
  raw Feature cancellation additionally requires its configured Canceller's
  exact same-Kernel ownership before any callback. Unproven/foreign cancellers
  and substitute/custom/dynamic child approval routes reject before dispatch and need
  reconciliation by their actual owner. No schema changes or backfill. See
  [independent audit and regressions](../audits/2026-11-01-pr82-feature-route-proof.md).

- **PR #82 mixed ancestry and Interaction callback fences:** Cancellation
  now follows both RunRelation and frozen/Item ownership across Application
  intermediaries, preventing native grandchildren from escaping a successful
  parent cancellation. Child response callbacks recheck frozen parents before
  and after claiming their effect. A pre-dispatch rejection follows the
  existing no-effect reset; prior unknown callbacks remain fenced. See
  [second independent audit](../audits/2026-10-31-pr82-mixed-scope-and-interaction-parent-fence.md).

- **PR #82 direct-target and Application subtree cancellation:** Direct
  external RunRelation Subtasks now retain an unverified cancellation intent
  rather than treating local absence or budget revocation as success.
  Subtask confirmation requires full subtree cleanup, even for terminal
  parents. Application roots and intermediate parents use the same durable
  cancellation fence for nested effects; unresolved Running children block
  success, and exact terminal Application ownership permits intent recovery
  without a Kernel Run. Handoff child verification now matches Kernel's
  canonical ID/Goal/RequestID request semantics while preserving exact
  Actor/Thread provenance. See [independent audit](../audits/2026-10-31-pr82-subtree-cancellation-and-canonical-identity.md).

- **PR #82 final terminal-descendant cancellation correction:** All three
  public cancel entrypoints (`Cancel`, `CancelInvocation`, `CancelSubtask`)
  no longer equate a terminal parent Turn/Invocation/Subtask with complete
  physical descendant cleanup. Local RunRelation children are cancelled
  even after their parent Failed/Completed. Related child Runs missing in
  the Harness Kernel remain **unverified**, not automatically no-effect:
  an explicit `ErrRuntimeCancellationUnverified` preserves the existing
  cancellation intent. Frozen Handoffs with definitive no-effect receipts
  and a failed Agent admission with no Kernel Run or descendants retain
  their existing safe paths. No new schema, RPC, state machine, router or
  compatibility shim. See [terminal descendant remediation](../audits/2026-10-31-pr82-terminal-descendant-cancellation-hardcut.md).

- **Final PR #82 re-audit closure:** Delegated Subtasks no longer project
  an unrelated local Run by ChildRunID, or use that mistaken terminal status
  to skip remote `CancelSubtask`. Only a fixed same-Kernel read-only route
  with complete frozen child provenance may materialize its local Run;
  remote/unproven routes retain the durable Handoff outcome. Custom
  RuntimeCancellers require an authoritative same-Kernel terminal receipt
  before a successful cancel may close its intent. A root Run which was
  already Failed/Completed can safely finish descendant cleanup and project
  that actual terminal state without deadlocking against its own intent;
  unfinished external cleanup preserves resumable intent. New
  `ErrRuntimeCancellationUnverified` is an explicit pre-stable behavioral
  hard cut, not a second cancellation protocol. See
  [final re-audit corrections](../audits/2026-10-31-pr82-subtask-custom-cancel-and-terminal-root-hardcut.md).

- **PR #82 independent final-Head cancellation/read reconciliation:** All
  native Kernel cancellers must use the exact Harness Kernel Runtime; a
  different pointer is rejected at composition and before physical Cancel.
  Root `Refresh` cannot project a terminal Kernel state into an already
  partially cancelled Turn while an unresolved cancellation intent remains.
  Only the original Cancel owner after verified descendant cleanup may commit
  that projection. Handoff `RefreshInvocation` cannot resolve a remote child
  from a coincidental local Kernel Run; it requires an explicitly fixed
  same-Kernel ChildRunner and the original frozen delegation/parent identity.
  Dynamic/external child routes fail closed, preserving remote reconciliation.
  These are deliberate beta hard cuts, not compatibility bridges; see
  [final independent merge-audit corrections](../audits/2026-10-31-pr82-independent-final-merge-three-p1-remediation.md).

- **Indexed child parent and root/child API boundary:** Child
  `Start*Invocation` requires an explicit same-Turn parent Item and uses
  `Store.GetItem` instead of scanning the entire Timeline at admission.
  `RefreshInvocation`/`ResumeInvocation` reject root Invocation IDs;
  root reads go through `Refresh(turnID)` and native Agent continuation
  through `ResumeTurn(turnID)`. The physical-dispatch parent liveness
  fence verifies both root liveness and the *exact root Attempt frozen at
  child admission*, even when an ancestor Item has no Invocation owner.
  Child and all delegated Agent Invocations (RoleID or MemberID) also freeze every intermediate
  owner Attempt inside hashed `Invocation.Input.harnessRoot.parents`;
  an old grandchild cannot attach to a retried parent despite a live root.
  Prior Accepted children cannot replay, retry or resume under a newer
  root or ancestor Attempt. Final root checks use
  an indexed primary-key read. Host Application roots may own Application
  children without phantom Kernel Runs, but not native Kernel children.
  Non-root Application owners in `Accepted` cannot authorize descendants
  before their durable Host-effect claim; admission and the final
  pre-callback check both reject them.
  Root/intermediate Retry is blocked during any unresolved Running child
  Application effect or open Turn physical grant (Turn-wide conservative
  fence, including sibling effects). Old incomplete child records lack the
  complete proof and must be drained or isolated before rollout.
  Every Handoff physical start, including MemberID-only delegation, uses
  a durable child-owned grant and post-grant ancestor fence; unknown
  external outcomes cannot clear the grant or silently rerun StartOrLoad.
  The Handoff Coordinator verifies the actual ChildRunner Run ID, a
  recognized Kernel status and an authorized Agent or `a2a.remote` shadow
  kind before projecting LoadRun, StartRun or Refresh results; invalid
  evidence leaves the Handoff grant unresolved rather than presenting a
  synthetic successful child outcome. MemberID no longer bypasses the
  child Invocation and physical grant. The same frozen identity now
  distinguishes Role and Member Handoff children from local Agent Invocations:
  child `RetryInvocation` and `ResumeInvocation` reject routed Handoff execution
  before Attempt rotation or a new dispatch grant, and both forms exclude
  supervisor Context Window history on Run Resume. The obsolete native
  `startRetriedRole` fallback is deleted. Handoff status receipts must match
  the full execution envelope frozen in the child's hashed Invocation Input:
  destination Member/Role identity and revisions, Goal, Instructions, Model,
  ModelOptions, tool keys, hosted grants and limits. Only outcome fields may
  change. The independent persisted proof prevents custom ChildRunners from
  laundering in-place mutations of shared slices into valid receipts.
  Mismatches retain the physical grant for explicit read-only investigation
  or quarantine, never auto-replay. ModelOptions preserve the canonical
  `encoding/json` wire representation; equivalent original whitespace and
  escaping cannot spuriously fail a frozen-scope check.
  An external Handoff child absent from the Harness-local Kernel is **not**
  proven cancelled. Both root Turn and child cancellation now return
  `ErrHandoffCancellationUnverified` if its physical dispatch may have
  entered the external ChildRunner, retaining the child Attempt and active
  cancellation fence. Never-dispatched or definitively pre-effect-rejected
  grants can still be cancelled without creating a remote Run. A live A2A
  shadow Run is not a valid remote cancellation receipt: native Kernel Cancel
  is rejected unless Host composition supplies an externally responsible
  `RuntimeCanceller`. Pre-hard-cut children without frozen root proof are
  also unverified. No generic remote cancel RPC, synthetic terminal snapshot, compatibility route,
  additional Store API, SQL DDL, Kernel schema or status migration.
  See [ADR 0015](../adr/0015-indexed-child-ownership-and-root-entry-boundary.md),
  [PR #82 Handoff source/receipt correction](../audits/2026-10-31-pr82-handoff-provenance-and-receipt-hardcut.md),
  [PR #82 frozen execution receipt correction](../audits/2026-10-31-pr82-handoff-frozen-execution-receipt-remediation.md),
  and [PR #82 remote cancellation correction](../audits/2026-10-31-pr82-remote-handoff-cancellation-remediation.md).

  Handoff also requires exact Tenant/Actor/Thread identity on observed

  A further independent P1 audit reproduced a FailFast Parallel Team

  [PR #82 RunRelation-descendant retry review](../audits/2026-10-31-pr82-composite-runrelation-retry-hardcut.md).

  persisted transcript consumers from `Message.Content: string`
  to an **ordered `[]model.ContentPart`**. Plain text is represented
  as `model.TextParts(text)`; legacy JSON string Content does not
  decode, and media sources are strictly typed HTTPS URLs or
  Provider-scoped `file_id` references. OpenAI Responses and Anthropic

  when managed Context budgets apply; archived media is retained
  without promoting URLs or File IDs to system guidance. No Host

  Drain/quarantine old nonterminal string-Content ModelInvocations
  instead of guessing hashes or replaying external effects.

  result dispositions are closed to `read`/`committed`/`pending`.
  Invalid or error-free rejected receipts never release shared Tool
  quota. See [PR #77 independent correction](../audits/2026-10-30-pr77-independent-tool-retry-disposition.md).
- Agent Tool execution in both direct and RunExecution modes now commits
  the exact Tool Call ID before physical dispatch and refuses automatic
  replay on unknown outcomes. Pre-effect model-correctable errors stay
  supported; after calling the Handler they require an explicit original-ID
  no-effect rejection receipt. See [ADR 0013](../adr/0013-uniform-tool-effect-intent-and-receipts.md).
- Shared Tool budgets retain previously Dispatched/Held reservations instead
  of reentering the physical Handler, and support exact read-only COMMIT
  reconciliation. Built-in Capability Tool receipt execution IDs now match
  their parent Model Tool Call, not the child Invocation ID.

- Independent PR #76 admission review closed the Host-only Application
  race after retry Attempt CAS and after Application effect-claim CAS.
  Parent ancestry is revalidated at the last pre-Executor boundary; a
  rejected claimed Attempt is durably classified as no physical effect,
  without replaying or fabricating an external business receipt.
- Child Harness Invocation retries preflight root Kernel liveness and the
  complete parent Item/Invocation ancestry before rotating Attempt/Run identity.
  Post-grant parent fencing remains authoritative for concurrent cancellation;
  Host-only Application children are not required to own Kernel Runs.
- Root Harness invocation retries require their original frozen Actor
  and Kernel Thread in hashed Invocation Input, and fail before Attempt CAS
  when those values are absent. The old Session identity fallback is deleted
  rather than carried as a migration bridge.
- Provider Router, OpenAI and Anthropic adapters relocate from Core's
  `provider` package to the standalone
  `github.com/orz-i/Gaoge-Agent-Runtime/go/agent-runtime-provider`
  module. Imports targeting the old path fail to compile by design.
- Provider-neutral `model.Client`, stream, Tool receipt, signed/encrypted
  replay and durable ModelInvocation data remain owned by Core/Agent.
- Harness removes the implicit `Runner.Start` default-Agent entry point. Hosts
  must explicitly select `Runner.StartAgentTurn`, `StartTeamTurn`,
  `StartWorkflowTurn`, `StartGroupChatTurn`, or `StartApplicationTurn`.
  This changes only the Go API and Host selection, not durable intent/receipt
  or Kernel execution semantics. See [ADR 0012](../adr/0012-host-selected-capabilities-and-external-model-providers.md).
- Owner approvals require the exact checkpoint ID in Go SDK, HTTP v1 and
  TypeScript; older Turn-only calls are invalid. Native Agent pending
  approvals without a committed Tool/call/checkpoint binding fail closed,
  rather than being inferred from old payloads. See the
  [breaking-change ledger](../breaking-changes.md).
- A Hosted Tool without an explicit terminal status is no longer considered
  completed. Stable-ID calls retain pending budget receipts until a valid
  terminal fact is received. Missing-ID unfinished calls are not
  automatically reconcilable: the Model reservation remains held (including
  its native quota), and the Host must explicitly reconcile or quarantine
  instead of repeating physical effects.
- Named external Model Providers now require an immutable, nonsecret binding
  fingerprint. Router registration requires explicit Host `Binding.Identity`;
  OpenAI/Anthropic HMAC the actual Endpoint, credential and wire protocol.
  Missing or changed proof blocks pending recovery before physical dispatch.
  Pre-stable pending ModelInvocations have an incompatible request hash and
  must be drained or quarantined before adopting this candidate.
- The Provider-powered task-agent sample is a non-published nested development
  module; the public Harness module no longer requires a vendor adapter.
- Release metadata, workspace checks, clean external consumers and tags
  cover eleven Go modules with identical prerelease versions.
- Additional Harness governance is tracked in the same
  [breaking-changes ledger](../breaking-changes.md).

## Mandatory adoption and verification

Update every Core, Provider, Harness, HTTP, SQLite and other optional module
to the same beta.24 release cohort; do not mix a provider module from a new
candidate with an older Core. Stop old workers and inventory outstanding
nonterminal Runs/Invocations. For unavailable/changed Provider bindings,
drain or quarantine before resuming. Unknown physical effects are not proof
of rollback or authority for retry.

Run `make check` and required full Beta security/integration gates, including
real PostgreSQL/Redis and optional OpenTelemetry deployment checks. After
protected review, coordinate a root tag and all eleven module tags to the
same commit. Release automation must pass
`node scripts/check-release.mjs --published` with `GOWORK=off` and no
filesystem replacements. Source-level tests alone cannot authorize release.

No compatibility import paths, schema migration, synthetic execution
state machine, general-purpose FeatureDriver, or automatic Provider switch
are shipped. Named Provider bindings now require immutable fingerprint proof;
first-party adapters detect same-name Endpoint and credential changes, while
custom network transports still require correctly rotated Host binding scopes.
