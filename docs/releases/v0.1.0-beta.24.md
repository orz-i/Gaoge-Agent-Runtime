# Agent Runtime v0.1.0-beta.24 — architecture hard-cut candidate

**Status: unreleased.** Do not install the candidate Go modules from remote
tags before the reviewed cohort is published. Beta.23 remains immutable.

## Changes

- **Indexed child parent and root/child API boundary:** Child
  `Start*Invocation` requires an explicit same-Turn parent Item and uses
  `Store.GetItem` instead of scanning the entire Timeline at admission.
  `RefreshInvocation`/`ResumeInvocation` reject root Invocation IDs;
  root reads go through `Refresh(turnID)` and native Agent continuation
  through `ResumeTurn(turnID)`. The physical-dispatch parent liveness
  fence additionally verifies root Invocation and authoritative Kernel
  Run liveness even when an ancestor Item carries no Invocation owner;
  Application roots use their Invocation because they have no Kernel Run.
  Root `RetryInvocation` remains unchanged. No compatibility route,
  additional Store interface, SQL/Kernel schema or status migration.
  See [ADR 0015](../adr/0015-indexed-child-ownership-and-root-entry-boundary.md).

- **Host command presentation hard cut:** Harness command descriptors now
  freeze executable child Capability identity, version, type, source and
  arguments Schema only; slash triggers, display names and descriptions are
  exclusively Host-owned. `FirstPartyCommandDescriptors` and
  `CommandCatalog.Resolve` are deleted. The `/harness/commands` HTTP
  discovery route, OpenAPI operation and TypeScript `harness.commands` client
  are removed with no replacement. The Host must supply its own explicit
  Team/Workflow authorization and input Schemas; legacy persisted command
  metadata is rejected, not silently reinterpreted. See
  [ADR 0014](../adr/0014-host-command-presentation-boundary.md).

- **P3 breaking Model Message:** migrate all Go Host, Provider and
  persisted transcript consumers from `Message.Content: string`
  to an **ordered `[]model.ContentPart`**. Plain text is represented
  as `model.TextParts(text)`; legacy JSON string Content does not
  decode, and media sources are strictly typed HTTPS URLs or
  Provider-scoped `file_id` references. OpenAI Responses and Anthropic
  Messages support ordered user text/image/PDF references; referenced
  audio (despite being represented in the Core union) is explicitly
  unsupported by these adapters, failing before network dispatch.
  Multi-modal media requires exact provider-aware token counting
  when managed Context budgets apply; archived media is retained
  without promoting URLs or File IDs to system guidance. No Host
  attachment upload API, Schema upgrade or bridge is introduced.
  Drain/quarantine old nonterminal string-Content ModelInvocations
  instead of guessing hashes or replaying external effects.
  See [P3 multi-modal hard-cut audit](../audits/2026-10-30-model-message-multimodal-hardcut.md).

- Harness `Store` implementations must now support
  `GetItem(context.Context, string) (harness.Item, error)` by
  immutable global ID. Child parent-execution liveness checks use
  targeted indexed reads rather than full Turn Item materialization;
  Memory `ListItems` uses binary-search cursor paging. Existing
  parent/cancellation guards and PostgreSQL primary-key schema
  remain unchanged. See [indexed parent Item audit](../audits/2026-10-30-harness-parent-item-indexed-reads.md).

- Hosted Tool budget settlement now requires the Provider's actual
  nonblank Call ID **even for terminal** completed/failed/cancelled
  statuses; anonymous facts cannot count as distinct physical effects.
  The original dispatched Model/native reservation remains Held across
  restart, and a mixed anonymous/identified response cannot partially
  settle. Historical anonymous numeric charges are preserved but
  marked incomplete and excluded from verifiable per-key usage. No
  synthetic IDs or automatic migration; see the
  [accounting hard-cut audit](../audits/2026-10-30-hosted-anonymous-terminal-accounting.md).
- Independently audited Tool retry hard cut: `RetryableExecutionError`
  alone is not permission to physically resend. Retry requires
  a trusted original-ID `rejected` no-effect receipt; successful Tool
  result dispositions are closed to `read`/`committed`/`pending`.
  Invalid or error-free rejected receipts never release shared Tool
  quota. See [PR #77 independent correction](../audits/2026-10-30-pr77-independent-tool-retry-disposition.md).
- Agent Tool execution in both direct and RunExecution modes now commits
  the exact Tool Call ID before physical dispatch and refuses automatic
  replay on unknown outcomes. Pre-effect model-correctable errors stay
  supported; after calling the Handler they require an explicit original-ID
  no-effect rejection receipt. See [ADR 0013](../adr/0013-uniform-tool-effect-intent-and-receipts.md).
- Shared Tool budgets retain previously Dispatched/Held reservations instead
  of reentering the physical Handler, and support exact read-only COMMIT
  reconciliation. Built-in Capability Tool receipt execution IDs now match
  their parent Model Tool Call, not the child Invocation ID.

- Independent PR #76 admission review closed the Host-only Application
  race after retry Attempt CAS and after Application effect-claim CAS.
  Parent ancestry is revalidated at the last pre-Executor boundary; a
  rejected claimed Attempt is durably classified as no physical effect,
  without replaying or fabricating an external business receipt.
- Child Harness Invocation retries preflight root Kernel liveness and the
  complete parent Item/Invocation ancestry before rotating Attempt/Run identity.
  Post-grant parent fencing remains authoritative for concurrent cancellation;
  Host-only Application children are not required to own Kernel Runs.
- Root Harness invocation retries require their original frozen Actor
  and Kernel Thread in hashed Invocation Input, and fail before Attempt CAS
  when those values are absent. The old Session identity fallback is deleted
  rather than carried as a migration bridge.
- Provider Router, OpenAI and Anthropic adapters relocate from Core's
  `provider` package to the standalone
  `github.com/orz-i/Gaoge-Agent-Runtime/go/agent-runtime-provider`
  module. Imports targeting the old path fail to compile by design.
- Provider-neutral `model.Client`, stream, Tool receipt, signed/encrypted
  replay and durable ModelInvocation data remain owned by Core/Agent.
- Harness removes the implicit `Runner.Start` default-Agent entry point. Hosts
  must explicitly select `Runner.StartAgentTurn`, `StartTeamTurn`,
  `StartWorkflowTurn`, `StartGroupChatTurn`, or `StartApplicationTurn`.
  This changes only the Go API and Host selection, not durable intent/receipt
  or Kernel execution semantics. See [ADR 0012](../adr/0012-host-selected-capabilities-and-external-model-providers.md).
- Owner approvals require the exact checkpoint ID in Go SDK, HTTP v1 and
  TypeScript; older Turn-only calls are invalid. Native Agent pending
  approvals without a committed Tool/call/checkpoint binding fail closed,
  rather than being inferred from old payloads. See the
  [breaking-change ledger](../breaking-changes.md).
- A Hosted Tool without an explicit terminal status is no longer considered
  completed. Stable-ID calls retain pending budget receipts until a valid
  terminal fact is received. Missing-ID unfinished calls are not
  automatically reconcilable: the Model reservation remains held (including
  its native quota), and the Host must explicitly reconcile or quarantine
  instead of repeating physical effects.
- Named external Model Providers now require an immutable, nonsecret binding
  fingerprint. Router registration requires explicit Host `Binding.Identity`;
  OpenAI/Anthropic HMAC the actual Endpoint, credential and wire protocol.
  Missing or changed proof blocks pending recovery before physical dispatch.
  Pre-stable pending ModelInvocations have an incompatible request hash and
  must be drained or quarantined before adopting this candidate.
- The Provider-powered task-agent sample is a non-published nested development
  module; the public Harness module no longer requires a vendor adapter.
- Release metadata, workspace checks, clean external consumers and tags
  cover eleven Go modules with identical prerelease versions.
- Additional Harness governance is tracked in the same
  [breaking-changes ledger](../breaking-changes.md).

## Mandatory adoption and verification

Update every Core, Provider, Harness, HTTP, SQLite and other optional module
to the same beta.24 release cohort; do not mix a provider module from a new
candidate with an older Core. Stop old workers and inventory outstanding
nonterminal Runs/Invocations. For unavailable/changed Provider bindings,
drain or quarantine before resuming. Unknown physical effects are not proof
of rollback or authority for retry.

Run `make check` and required full Beta security/integration gates, including
real PostgreSQL/Redis and optional OpenTelemetry deployment checks. After
protected review, coordinate a root tag and all eleven module tags to the
same commit. Release automation must pass
`node scripts/check-release.mjs --published` with `GOWORK=off` and no
filesystem replacements. Source-level tests alone cannot authorize release.

No compatibility import paths, schema migration, synthetic execution
state machine, general-purpose FeatureDriver, or automatic Provider switch
are shipped. Named Provider bindings now require immutable fingerprint proof;
first-party adapters detect same-name Endpoint and credential changes, while
custom network transports still require correctly rotated Host binding scopes.
