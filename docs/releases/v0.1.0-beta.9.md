# Agent Runtime 0.1.0-beta.9

Nested workflows now expose their pending input through the parent Harness Turn. Concurrent child waits are presented one at a time under the existing durable interaction contract. Resolving an interaction resumes its exact child execution, then advances the existing parent; a replay cannot resolve a later wait.

Parallel and map effect children receive separate immutable relations, enabling cancellation of every descendant. Existing relation identities are retained when recovering historical executions. Workflow waits in the subtask projection are no longer decoded as tool approvals.

No HTTP schema, persistence schema, or TypeScript API changes. Existing immutable definitions and runs remain readable. Hosts compose the existing `WorkflowWaitInteractionProjector` and Workflow registry as before.

Regression coverage exercises two parallel child workflows with successive waits, refresh, repeated responses, completion, and cancellation of both children. The host integration additionally verifies that edits during a wait cannot replace frozen child definitions.
