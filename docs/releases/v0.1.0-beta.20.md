# Agent Runtime 0.1.0-beta.20

An Agent Tool can now wait for an external durable receipt without repeatedly
calling its executor or model. Its Run remains `running`; the Tool is counted
once when the saved receipt is consumed. Native local Agent delegation and
feature capability parents wait for durable child completion. Custom/remote
delegation and omitted or `scheduled` pending descriptors retain their existing
observation behavior.

`tools.ExecutionResult.Pending` optionally carries a typed `PendingExecution`.
An `external_result` requires a stable operation ID, a lowercase SHA-256 input
digest and a frozen deadline. `agent.Runner.QueryPendingTool` exposes the
committed wait registration. `NotifyExternalToolResultReady` accepts matching
identity plus a stable signal ID; it carries no result payload or authorization.
Identical notifications are idempotent, including after consumption. Conflicting
identity, cancelled Runs and expired calls cannot be revived.

Hosts must authorize the Actor/Run, make an operation claimable only after its
matching wait is committed, and persist its result receipt and retryable
notification outbox before signaling readiness. On resumption the executor reads
that receipt. This release provides in-process ports, not a public notification
HTTP endpoint, browser claim/receipt handlers or a server execution sandbox.
See [the host sequence](../external-tool-wait.md).

Wait generations are stored in existing transition JSON and continuation
payloads. Deadline/readiness delivery uses the current Run revision and checks
the wait generation. Normal waiting has one deadline projection and no
per-second state commits. Hosts wrapping the first-party Agent resumer must
preserve the optional `continuation.ToolWaitResumer` contract. Child-terminal
reconciliation also recovers a notification consumed before its parent wait was
committed.

HTTP v1 adds optional `RunSnapshot.pendingTool`, containing only kind, call ID,
Tool key, deadline and readiness. The TypeScript client exports `PendingToolDTO`
and `toolWaitPhase`; it preserves Run lifecycle and ignores wait metadata for
terminal/input/budget-paused Runs. Operation correlation, input digests, signal
caches and private waiting state are excluded from ordinary HTTP projections.
Two new reviewed snapshots cover external and child waits across Go, OpenAPI and
the packed TypeScript consumer; existing fixtures are unchanged.

Upgrade all nine Go modules and the TypeScript client together to
`v0.1.0-beta.20`. No SQL schema migration is required, but older SDK cohorts do
not understand typed wait state or generation metadata. Once these waits have
been persisted, recover them with this cohort or a later supported release;
in-place downgrade is unsupported. Existing hosts implementing Store, Model,
Catalog or Executor ports gain no new required interface methods.

The release gate covers deterministic 60-second no-poll waits, duplicate and
conflicting signals, cancel/deadline races, crash recovery, authorized local
delegation and Team child recovery, safe HTTP projection, real PostgreSQL 16
wait/outbox recovery and real Redis 8 continuation reconstruction. The normal
quality, race, coverage, security, clean consumer and OpenTelemetry Collector
gates also apply.

The TypeScript archive is `orz-i-agent-runtime-client-0.1.0-beta.20.tgz` on this
GitHub prerelease. npm registry publication remains disabled for Beta releases.
