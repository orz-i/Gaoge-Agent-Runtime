# Agent Runtime 0.1.0-beta.11

This release promotes the OpenTelemetry adapter into the coordinated Beta
release cohort and strengthens repository quality gates. The beta.10 tags and
archive remain immutable.

## Changes

- Add `go/agent-runtime-otel` as the ninth released Go module. It converts the
  Runtime's content-safe structural observations into OpenTelemetry spans and
  low-cardinality metrics without owning the host's SDK, exporter, sampling,
  resource, Collector, or shutdown lifecycle.
- Keep prompt/completion, tool argument/result, workflow payload, and arbitrary
  content fields out of the telemetry contract. Metric attributes exclude Run,
  operation, and response IDs to avoid identity-driven timeseries cardinality.
- Add CI and release coverage gates for Go and TypeScript, plus Go/Node
  vulnerability gates. Refresh the TypeScript lint/test toolchain to patched
  dependency versions.
- Remove the PlanExecute runtime feature completely: the Go feature package,
  HTTP Plan routes, Harness capability/execution class, topology projection,
  OpenAPI capability contract, and TypeScript `client.plans` surface are gone.
  Planning is no longer a first-party Runtime kind.
- Add HTTP guard-path tests for Agent, Team, and Harness handlers, improving
  evidence for unavailable/invalid-request behavior.
- Document the package/layer architecture, observability signal model, and
  production deployment boundary. Agent Runtime remains an SDK/runtime
  component set rather than a canonical standalone server image.

## Upgrade notes

1. Upgrade all nine Go modules to `v0.1.0-beta.11` and use
   `orz-i-agent-runtime-client-0.1.0-beta.11.tgz` from this GitHub prerelease.
   Beta packages are not published to npm.
2. `go/agent-runtime-otel` is optional. Hosts that enable tracing construct a
   host-owned `trace.TracerProvider` and pass it to `runtimeotel.New`. Hosts that
   enable metrics construct a host-owned `metric.MeterProvider` and pass it to
   `runtimeotel.NewMetrics`. The host owns SDK readers/processors, exporters,
   resources, credentials, Collector topology, and shutdown.
3. The telemetry adapter does not change Kernel state, PostgreSQL/Redis schemas,
   HTTP v1, or TypeScript wire types. No data migration is required solely for
   observability.
4. Coverage and vulnerability checks are now part of the Beta release gate.
   Release environments need network access to the Go vulnerability database
   and npm advisory registry.
5. PlanExecute users must migrate before upgrading: there is no compatibility
   alias or deprecated endpoint in beta.11. Compose Agent, Workflow, Team,
   GroupChat, or host-owned application capabilities explicitly instead of
   depending on `plan_execute`.
6. Continue upgrading workers and SDK modules as one version cohort. Mixed
   beta.10/beta.11 workers are not covered by the compatibility gate; follow the
   forward-only procedure in the [integration contract](../integration-contract.md).

The release workflow must verify the complete root plus nine-module tag set and
pass `make check`, coverage, security, real PostgreSQL/Redis integration, and
the OpenTelemetry Collector trace/metric gate before publishing the TypeScript
archive.
