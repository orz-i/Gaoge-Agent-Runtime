# Agent Runtime 0.1.0-beta.23 — coordinated release candidate

**Status:** candidate prepared in `governance/kernel-runtime`; **not published** by the engineering change. Do not use the new version in a downstream application until the root and all **ten Go module tags** are present on the same reviewed `main` commit and the GitHub release workflow has passed.

This release candidate coordinates the Kernel execution-safety additions with its optional SQLite Store. The previous published `v0.1.0-beta.22` Core module does **not** contain the `ControlStore`, `ExecutionStore`, or related APIs required by SQLite. Using mixed `beta.22` / `beta.23` module versions is not supported.

## Included

- The existing six-status Kernel stays authoritative. Opt-in execution epochs and leasing, guarded approval/budget/cancel controls, native Agent intent/receipt and unknown-outcome handling, Store-backed quarantine, and identified-Apply evidence remain bounded, Feature-owned recovery mechanisms.
- SQLite is added as the **tenth coordinated Go module**, `github.com/orz-i/Gaoge-Agent-Runtime/go/agent-runtime-sqlite`. The adapter provides experimental private-Profile Kernel durability plus immutable `runrelation.Store` identity, with cross-process crash and rollback conformance. It does **not** implement automatic Team/Workflow child handoff, or Hosted/mobile product certification.
- Stage 6's bounded `decodeSnapshot` State-buffer optimization removes one duplicate copy after `database/sql.Scan` into caller-owned `[]byte`. Targeted large-State benchmarks and snapshot isolation/concurrent tests passed. No new public API or DDL is introduced by this optimization.
- Real PostgreSQL/Redis Hosted SDK wakeup protection prevents a stale, unconsumed nonterminal RunReady Job from being falsely ACKed based solely on later Run Revision changes. It is not Feature-specific consumption evidence or provider-side exactly-once assurance.

## Compatibility and upgrade

- Upgrade **all ten Go modules and the TypeScript client together** to `v0.1.0-beta.23`, after their coordinated publication. Use new immutable tags for every module; never move or retag `beta.22`.
- PostgreSQL Kernel execution and quarantine metadata adds columns/indexes under the existing migration/Host gate. Hosts with stored Runs must validate their migration/rollback path and restart/worker compatibility before enabling the new execution features.
- Stop old Harness workers before running `harnesspostgres.Migrate(db)` to install the single-root-per-Turn index `uk_harness_invocation_root`, then deploy upgraded workers. Historical duplicate roots or nonempty `parent_item_id` values that become empty under Go `strings.TrimSpace` reject migration and retain all records unchanged. Hosts must review the affected Run outcomes and external effects and reconcile the data before rerunning migration.
- Queue fingerprints now preserve exact JSON numbers and their lexical spelling. Re-enqueuing a Job persisted under the previous fingerprint rules may return `ErrConflict`; hosts must manually compare the stored Job and intended payload before deciding how to reconcile or retry it.
- SQLite's **first public Schema v1 remains unreleased** and its `PRAGMA user_version=1` does not change during prototype development. Earlier private experimental SQLite v1 files with incompatible DDL are **rejected fail closed**, not silently overwritten or migrated. Before future production release, define an explicit supported storage upgrade policy.
- The SQLite Windows file-URI correction adds no Windows ACL or directory-fsync certification. Existing private-Profile filesystem and durability requirements remain the Host's responsibility.
- Opt-in native Direct Agent recovery requires the Host to supply stable Run IDs and genuinely trusted tool/Provider commit reconciliation. A changed revision, a Queue ACK, or a timed-out effect is not COMMIT proof. Existing non-opted-in behavior remains supported within its documented limitations.
- Real product Host authorization, Provider physical idempotency, SQLite shared Profile/multi-device security, Android/iOS VFS, automatic child-terminal reconciliation, and production throughput/SLO are **not certified** by this Beta.

## Publication verification

Before publishing, merge the accepted change through the protected PR review and run the complete `make beta` gates (including coverage, reachable vulnerability scan, real PG16/Redis8, OpenTelemetry Collector). The publisher requires the root tag and all ten module tags to refer to the **same immutable commit**. The release workflow additionally runs:

```shell
node scripts/check-release.mjs --published
```

That command compiles and executes clean `GOWORK=off` consumers against actual tagged modules **without any filesystem `replace`**. The ordinary `make check` uses source-based coordinated replacements for pre-publication verification and is **not** evidence that unpublished tags are already downloadable.

After the tags exist, verify explicitly:

```shell
cd go/agent-runtime-sqlite
GOWORK=off GOFLAGS=-mod=readonly go test ./...
```

Before tags are published, this command may fail because `v0.1.0-beta.23` is not remotely resolvable. Do not solve it by checking `replace ../agent-runtime` into a published `go.mod`. The TypeScript Beta remains an archive attached to the GitHub Release; no npm registry publication is performed.
