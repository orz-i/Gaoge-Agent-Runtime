## v0.1.0-beta.4 Release Notes

### ✨ Feature

- Hosts can present Workflow approval and input waits as durable application-owned Harness interactions.
- Prepared tasks can explicitly isolate their conversation window while preserving cancellation and tracing.

### ⚡ Optimization

- Beta TypeScript packages are available as GitHub Release archives; npm publication is reserved for stable releases.
- Workflow recovery can restore the input request after its turn and invocation are already waiting.
- Upgrade note: custom `harness.WorkflowFeature` implementations must add `ResolveWait`; the SDK Workflow runner already supports it. HTTP v1 and persisted schemas are unchanged.

### 🐛 Fixed

- Resolving a Harness interaction now resumes the exact waiting Workflow and returns its result.
- Concurrent retries of the same accepted Workflow start no longer report a false failure when another worker has advanced the run.

## v0.1.0-beta.4 中文版本

### ✨ Feature

- 宿主可将 Workflow 的审批和输入等待映射为持久化的业务 Harness 交互。
- 已准备完整输入的任务可显式隔离对话窗口，同时保留取消与追踪上下文。

### ⚡ Optimization

- Beta TypeScript 包通过 GitHub Release 附件分发，正式发布前不推送 npm。
- Turn 和 Invocation 已进入等待状态后，恢复流程仍能补齐对应输入请求。
- 升级提示：自定义 `harness.WorkflowFeature` 实现需增加 `ResolveWait`；SDK 自带 Workflow runner 已支持。HTTP v1 与持久化表结构不变。

### 🐛 Fixed

- 提交 Harness 交互响应后，会恢复对应的 Workflow 并返回执行结果。
- 同一已受理 Workflow 的并发重试，不再因其他执行者已推进版本而被误报为失败。
